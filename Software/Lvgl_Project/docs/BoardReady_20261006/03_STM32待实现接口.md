# STM32 待实现接口与启动契约

> 2026-10-09 输入契约变更：实体按键消抖、单双击、长按与编码器解码现由 STM32 InputService 负责；旧 sample_inputs/set_key_map/submit_input 已删除。本文输入部分及原行号属于历史快照，新接入须使用 [实体输入架构与队列契约](../输入架构重构_20261009.md)，触摸与其余端口不变。


本轮提供正式软件端口，未编写 STM32 HAL 驱动。硬件型号、引脚、骑行17字段单位、24命令 value 语义、坐标系和存储事务仍以原接入指南核实内容为依据；本文件补充重构后的执行契约。全部结构成员及当前行号见 `当前STM32接口变量与回调清单.md/.csv`。

## 一次启动

1. BSP 初始化时钟、MPU/cache、FMC和32MiB SDRAM、QSPI（若字体/资源映射使用）、LTDC/ST7701S、DMA2D（可稍后）、输入驱动、TF/FatFs及持久化。屏幕时序、FMC地址及刷新参数来自BSP与原理图，UI不猜测。
2. 链接将 `.ui_sdram` 放到外部RAM。若使用 NOINIT，必须在FMC可用后清零该段；避免启动代码在FMC尚未初始化时触碰外部段。任何UI函数，包括注册函数，执行前需完成此步骤。
3. 建立单一、具优先级继承的 FreeRTOS mutex、各后台队列、UiTask任务标识与单调时钟。先不允许producer任务提交；backend结构和context需长期有效。
4. UiTask准备 `ui_stm32_startup_t`：runtime、resources_ready、display、services、history、preferences、navigation、maps、search、devices、font20/font24、sound、双raster及实际navigation_capabilities。后台功能未实现时仍可注册明确拒绝/报告失败的适配器，不能返回伪成功。
5. UiTask调用 `ui_stm32_startup(&startup)` 一次。它先校验资源、缓冲容量/32字节对齐/重叠/端口，再注册runtime、mutex和现有backend，`lv_init()`、`lv_tick_set_cb(ui_runtime_now_ms)`、display/input/fonts/sound/devices/background，最后执行一次 `ui_app_init()`。可选background不注册时无默认PC图片文件读取。
6. 启动成功后才放行InputTask、GNSS/FusionTask、StorageTask、Navigation/Map/SearchTask、ESP32Task。UiTask循环调用 `ui_stm32_ui_task_handler()`，根据LVGL返回deadline和板端调度策略睡眠/等待。不得另起任务运行LVGL handler或再调用model/page process。

启动已进入部分初始化后失败应记录fault并复位板端，不能第二次调用 `ui_app_init()` 来恢复。启动后不重新注册backend、不重新配置raster、不替换仍被LVGL使用的字体。注册入口和handler有UiTask检查，worker/ISR调用会拒绝。

## BSP/RTOS回调

| 已有类型/成员 | 板端待实现 | 上下文与约束 |
| --- | --- | --- |
| `ui_runtime_port_t.now_ms` | 单调32位毫秒时钟 | UiTask及worker同一时钟域；允许自然wrap；不使用UTC作耗时 |
| `now_us` | 可选单调微秒计数 | 用于handler耗时；缺省为ms×1000，精度仅毫秒 |
| `is_ui_task` / `is_isr` / `fault` | 任务身份/IPSR判断/故障处理 | 不做阻塞日志；fault策略由BSP决定 |
| `resources_ready` | 已初始化资源就绪检查 | 检查状态，不在此回调初始化HAL |
| `ui_stm32_service_port_t.lock/unlock` | FreeRTOS mutex take/give | 只任务；短邮箱拷贝；不能把critical section或spinlock当mutex；不嵌套I/O |
| `dispatch_command/cancel_command/tick` | command值复制到队列、取消通知、tick调度通知 | UiTask立即返回；队列bool只表示受理；完成后才ACK |
| `request_history_page_worker` | 通知StorageTask | 不在UI请求回调执行FatFs |
| `ui_stm32_display_port_t.start_flush` | 软件按stride行copy，或启动DMA2D | 只UiTask；返回DONE/ASYNC/FAILED有明确buffer所有权 |
| `wait_flush_complete` | 等待DMA完成通知，带BSP截止时间 | 只UiTask；ISR只FromISR通知；true表示DMA已不再占有pixels |
| `ui_device_connection_port_t.scan/connect` | 向ESP32排队扫描/连接请求 | 不直接改“已连接”；真状态由submit_device_status回报 |
| `ui_sound_backend_cb_t` | 复制声音事件与音量到音频队列 | void回调无法回传失败，BSP必须计数队列满；不等待播放结束 |
| `ui_background_port_t.load/release` | 可选常驻bitmap资源与生命周期 | load不得在运行期阻塞TF读取；返回预载/QSPI/SDRAM指针 |

邮箱mutex与LVGL内部锁是不同概念。此工程唯一UiTask，STM32 `LV_USE_OS=LV_OS_NONE`；不安装第二套LVGL FreeRTOS锁机制。BSP的mutex函数不能失败后继续执行临界区；超时/无效句柄必须走明确fault策略。

| 设备连接行：`ui_stm32_device_status_t` | `submit_device_status` | 5种device.kind，status64/feedback96；按kind合并最新状态；UiTask消费后调用页面API |
| 异步事件：`ui_event_t` | `publish_event` | 经过event bridge，worker不直接调用observer/page |

以上入口不是ISR API。ISR只复制到BSP的 `xQueueSendFromISR` / task notification，再由任务调用。BSP需要检查FreeRTOS允许调用FromISR API的中断优先级；不可照抄PC配置。

完整快照建议由一个FusionRecordTask发布。`submit_ride_patch`同时携带timer/session/UTC等公共元数据，多任务无序提交仍会产生覆盖风险；使用统一融合owner与单调版本/采样时刻解决。现有command dispatch返回false表示队列/受理拒绝，UI保持原REJECTED语义；不支持的硬件操作应由任务明确complete为FAILED并带BSP error_code，不能把入队true直接当成SUCCESS。

## InputTask

原始 `pressed_mask` 使用现有 `UI_HW_KEY_BIT(UI_HW_KEY_*)`。编码器四相状态解码/丢非法跳变/每detent归一化由BSP完成，InputTask只调用 `ui_stm32_services_sample_inputs(mask,encoder_delta,board_now_ms)`。短按、长按、去抖由现有 `ui_hardware_input` 处理；默认BACK禁用通用short/long，内部用已去抖BACK进入 `ui_back_key_gesture_update`，保持单击/双击/长按语义。板端不得再做另一套BACK手势。`set_key_map`仅输入开始前使用，修改BACK映射会关闭默认BACK双击路径。

触摸驱动一次完成校准、旋转、镜像并保持x=0..479、y=0..853，调用 `submit_touch(x,y,pressed,cancelled)`。同一缓存供UiTask的LVGL pointer indev读取，同时enqueue TOUCH_BEGIN/MOVE/END/CANCEL。不得手工调用按钮action。断连/锁屏/总线失败要提交CANCEL并使用最后有效校准坐标，不能用越界坐标导致release被拒绝。默认API要求单一InputTask串行提交输入。

## 显示与时间

第一阶段480×854 RGB565、PARTIAL、双小draw buffer（例如各40行38,400B）、一个SDRAM framebuffer819,840B。`start_flush`收到闭区间area及真实stride，BSP检查目标地址范围/格式/字节序；UI不配置LTDC/FMC/ST7701S时序。drawbuffer由BSP分配，UI不隐藏分配full framebuffer。

同步软件copy完成后返回DONE。异步DMA2D返回ASYNC，UI不立即flush_ready；LVGL9通过flush_wait回调在本轮handler中等待完成，随后由UiTask `lv_display_flush_ready()`。双buffer场景不能等下一轮handler才处理ready，否则LVGL本轮可能一直等。ISR只发notification，不调用LVGL。FAILED必须保证DMA已经不再持有pixels；若wait失败，port fault并fail-stop，防止仍被DMA占有的drawbuffer复用。

BSP负责D-cache clean/invalidate、MPU、DMA可达内存与必要barrier。PARTIAL写单framebuffer可能出现tearing，后续VBlank/双full方案需独立验证，本轮不假定已经实现。

UiTask使用注册的now_ms作为LVGL tick唯一来源，禁止同时lv_tick_inc。ride.sample_time_ms、quality[].sampled_at_ms、nav.sampled_at_ms、session.position_sampled_at_ms和InputTask now_ms都来自同一板端单调时钟。UTC独立用于存档日期；`now_utc`只读已缓存RTC/GNSS结果，未知为0，不在该回调阻塞I2C读RTC。

## Storage / 导航 / 搜索 / 字体

`ui_ride_history_storage_t`实现load/store及建议的load_checkpoint/store_checkpoint、load_page、append_record。store/append只有可恢复持久化完成后返回OK。启动的load及preferences.load在app_init期间同步调用，必须在显示循环开始前完成；历史掉电checkpoint恢复也可能在启动执行持久化写操作。运行期保存通过dispatch队列进入 `ui_stm32_services_commit_ride_worker()`，分页进入 `history_page_worker()`；UiTask现有tick发布结果。保存worker返回真实结果后，通过complete_command回报原command id，UI才改变保存状态。不要在UiTask调用同步commit_pending/prepare/load_page进行磁盘I/O。

`ui_preferences_port_t.load/store/request_worker`：启动读；运行期request_worker仅排队，StorageTask调用 `ui_stm32_services_preferences_worker()` 执行store。所有worker包装器拒绝UiTask/ISR调用。

导航/map/search在 `ui_app_init()` 前分别注册现有 `ui_nav_backend_t`、`ui_nav_map_backend_t`、`ui_nav_search_backend_t`。UiTask dispatch/request仅复制有界request并立即返回；Navigation/Map/SearchTask执行图校验、A*、raster生成、POI检索和HTTPS等待，然后submit/complete。read_at通过 `ui_offline_map_io_t`接FatFs/QSPI专属句柄，返回bool及实际size，不把完整路网读到stack。并发文件访问必须有明确owner/文件锁，不能共享被不同请求seek的FIL。read_at必须支持任意对齐的小目标地址；结构体整体32字节对齐不保证每个scratch成员都32字节对齐。BSP SDMMC读取优先使用独立cacheline对齐的DMA bounce buffer再copy，不直接假设这些成员可供DMA/cache整行操作。

raster沿用 `ui_nav_raster_begin/publish/abort/take/release`，worker只写WRITING槽；UiTask在draw间隙取与request_id匹配的READY槽，DISPLAY槽禁止worker改写。这些是服务层资源所有权API，无LVGL控件调用。

在线POI/HTTPS由ESP32实现，AC6 UI core只保留已有有界JSON解析/结果合并算法。BSP限制接收长度、token/depth及取消超时，结果不能自动设置已联网或真实GPS有效。当前地方库覆盖与导航定位精度保持现有功能，未通过重构承诺“搜哪都有”。

`font20/font24`经 `ui_text_register_fonts()` 注册长期有效lv_font_t；字体descriptor/fallback/bitmap在使用中不释放。静态MiSans子集只够已知UI与当前地点，未来在线POI字形不保证存在；现有prepare会用`?`替换缺字并返回false。BSP应提供20/24像素匹配的完整中文覆盖或font fallback，优先QSPI memory-map/SDRAM预载；get_glyph_dsc/get_glyph_bitmap在UiTask被调用，不能临时阻塞FatFs或HTTP取字。中文字形覆盖、宽度一致性与cache峰值仍需实板验收。

## 诊断与实板验收

`ui_stm32_services_get_diagnostics()`任务上下文读取input_queue_drop、event_bridge_drop/event_forward_failure、command_drop/timeout/late_ack及runtime counters。late_ack来自现有unexpected_results，是迟到/重复/未知ACK聚合值，不能解释成精确迟到次数。runtime还包含context_rejected、mailbox_failure、display_failure、encoder_clipped、handler_calls/last_us/max_us。handler时间包含flush等待，非纯CPU渲染时间。latest-value mailbox正常合并不计drop；需要逐条可靠的数据必须由BSP使用可靠队列。

后续必须补BSP queue满/FromISR失败计数、FreeRTOS stack high-water、SDRAM/heap峰值、flush/DMA/TF耗时、GNSS时龄、掉电事务和长期动画导航测试；这些是板端性能与功能验收，不属于本轮已通过的主机测试。
