## 大内存

ARM ELF中≥1KiB对象165个，可写62个；可写大对象2,159,212B均在.ui_sdram，无遗漏。连同较小段对象，.ui_sdram已编译静态符号合计2,161,724B。未包含段对齐padding、未进入库的BSP缓冲和其他固件组件。

| 类型/容量 | ARM字节 | 所有权与使用 |
| --- | --- | --- |
| LVGL builtin heap | 1,048,576 | UiTask；LV_ATTRIBUTE_LARGE_RAM_ARRAY映射UI_LARGE_RAM |
| history100记录model / working100记录 | 325,640 / 325,600 | UiTask model；working通过atomic交给StorageTask |
| ui_ride_record_t / checkpoint | 3,256 / 3,304 | 常驻事务scratch；不是Task栈数组 |
| ui_nav_map_frame_t | 28,520 | mutex邮箱及MapTask独占workspace |
| JSON tokens2048+name/detail scratch | 33,552 | SDRAM，单次try-claim，重入失败立即返回 |
| ui_offline_route_t | 327,744 | caller在SDRAM分配；完整route不复制进LVGL模型 |
| A*当前155061节点 | 3,721,464 | nodes×24；caller-owned；271799条边从read_at读 |
| tile cache metadata / 每像素槽 | 35,212 / 131,072 | SDRAM；8槽1,048,576；32槽4,194,304 |
| framebuffer480×854 RGB565 | 819,840 | BSP SDRAM单fb；LTDC扫描 |
| 双draw buffer各40行 | 2×38,400 | BSP DMA可达RAM；flush完成才复用 |
| 双raster各768² RGB565 | 2×1,179,648 | MapTask写非DISPLAY槽；UiTask采纳 |

上述大静态对象+单fb+双40行draw+双raster+8像素缓存槽+A*+双完整route+graph/tiles/cache/worker帧等示例合计10,917,600B（约10.41MiB）。32MiB SDRAM从容量上有余量，但不能据此断言不会OOM：还需中文字体、ESP32接收、动态LVGLlayer、RTOS任务、其他业务、alignment以及峰值/泄漏测试。固定LVGL heap1MiB仍需实际high-water验证，容量不足应调整BSP/配置预算，不能删UI来掩盖。

只读≥1KiB符号汇总2,560,836B，其中应用库1,615,052B。此值是归档对象统计，最终dead stripping会改变大小；不能当成最终Flash image。H743内部2MiB Flash是否足够必须看实际链接map；可将字库/图片放QSPI映射并由BSP安排scatter，UI未硬编码地址。

原大Task栈临时对象改成UiTask-only常驻workspace，包括history/report/nav snapshot、地图label碰撞、dock card及nav request临时区。graph CRC4096、tile CRC1024与decode4096归caller结构；worker传入的完整route/frame/cache等必须使用UI_LARGE_RAM常驻区或明确SDRAM allocator，禁止局部大数组。≥1KiB静态扫描和编译frame警告不是完整调用栈上界；JSON深度16递归、vendor render以及HAL/FatFs栈还要靠编译call graph/RTOS高水位验证。

## C11/atomic

全部应用C源使用C11；AC6 Cortex-M7真实编译通过。保留stdatomic、release/acquire/compare_exchange语义。使用点逐行见 `C11原子使用点.csv`。

| 模块 | 原子用途 | 与mutex关系 |
| --- | --- | --- |
| ui_ride_history_repository.c | s_job_state：idle→frozen→worker→completed | UiTask/StorageTask job发布与所有权；单次CAS，不等待自旋 |
| ui_online_places.c | s_json_busy：保护公共JSON与merge workspace | 一次test_and_set，忙则FAILED；backend需队列串行，不伪装RTOS mutex |
| ui_offline_map.c | s_map_busy：保护rank数组 | 一次test_and_set，忙则UNAVAILABLE；worker可稍后重试 |
| ui_runtime.c | 诊断uint counters/timing | relaxed统计；要求ATOMIC_INT_LOCK_FREE==2；只有UiTask写handler峰值 |
| PC ui_pc_concurrency.c | 保留原PC默认spinlock | 不在STM32源清单；STM32必须RTOS mutex |

诊断原子多字段快照不是同一瞬间的全局事务快照；任务身份、clock、backend和字体注册遵循“先注册，后放行producer”，运行期不更换context。没有为兼容ARMCC5删除原子操作；工具链要求AC6/C11。

## 阻塞与线程调用审查

公共UI/services/STM32没有HAL_I2C/UART、FatFs或WinHTTP调用。底层read_at与storage/font/backend回调的具体实现仍由BSP保证，不能由静态UI源码检查证明任意未来BSP回调均不阻塞。`潜在阻塞调用点.csv`保留源位置，以下是批准的执行位置。

| 路径 | 允许位置 | UiTask运行期限制 |
| --- | --- | --- |
| preferences.load；history.load/load_checkpoint及启动recovery | 启动一次，producer未放行 | 启动完成后不得周期性同步load |
| history.store/checkpoint/append/load_page；preferences.store | StorageTask worker | request/dispatch只复制/通知；UiTask process只应用结果 |
| graph open CRC、map/tiles/places/route read_at、A*、raster/LZ4、JSON解析 | Navigation/Map/Search/StorageTask | 不在按钮/动画/LVGLtimer回调执行 |
| font glyph查询、bitmap background load | UiTask可能调用 | 必须常驻/内存映射/预载；不能阻塞TF/网络 |
| command/nav/map/search/device/sound callback | UiTask | 有界复制queue并立即返回；队列满显式失败/计数 |
| flush_wait等待DMA | 唯一UiTask的LVGL9专用flush_wait | 显示port唯一明确等待例外，截止时间与FromISR通知由BSP实现 |

对STM32端口的LVGL调用已逐点整理 `STM32显示与LVGL调用点.csv`：startup调用init/tick、display创建/flush、pointer创建/read都在UiTask；没有worker或ISR中直接调用LVGL。设备状态通过mailbox由handler应用到page。模型observer/process和page setters仍为UiTask API，不因submit线程安全而成为任意线程API。现有worker包装器拒绝UiTask；formal submit/complete拒绝ISR；ISR只唤醒任务。

UI内保留现有纯内存处理（如stage冻结100记录及几何绘制），这是冻结功能所需逻辑，没有在本轮改动它的算法/体验。它们耗时和邮箱copy占锁时间需要实板测量；不能把“没有文件I/O”理解为“执行时间为零”。

## fake成功、时间与诊断

STM32无默认天气温度、速度/GPS/导航回放、Wi-Fi/BLE已连接注入或命令自动成功路径。ride初始quality_known=true但无valid/capability；navigation无valid；weather invalid；启动连接/GNSS状态由服务层提交无数据初值。真实backend必须以能力/有效性与FAILED/UNSUPPORTED表达缺失，排队成功不代表硬件执行成功。

`lv_tick_set_cb(ui_runtime_now_ms)`唯一tick来源；所有采样用同一单调时钟，不再lv_tick_inc。handler耗时含等待DMA；now_us缺省时毫秒量化。input/event/command drop、timeout、unexpected ACK、mailbox failure、上下文拒绝、encoder裁剪、display失败可观察。最新快照正常合并不等同队列丢失；需要逐条采样/持久化的后台记录必须使用自己的可靠队列。
