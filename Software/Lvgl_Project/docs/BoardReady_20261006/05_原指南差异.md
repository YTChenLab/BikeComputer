# 与原接入指南、接口清单的明确差异

> 2026-10-09 输入契约变更：实体按键消抖、单双击、长按与编码器解码现由 STM32 InputService 负责；旧 sample_inputs/set_key_map/submit_input 已删除。本文输入部分及原行号属于历史快照，新接入须使用 [实体输入架构与队列契约](../输入架构重构_20261009.md)，触摸与其余端口不变。


事实来源仍为 `docs/STM32接入说明_20261006/LVGL到STM32全流程接入指南.md` 与 `STM32接口变量与回调清单.md/.csv`。本轮没有改写这些文件，保留硬件引脚/数据单位/命令含义及其原始源码基线。它们描述的是重构前状态；当前实现事实与执行合同以源码及本目录附录为准。

| 原资料位置/内容 | 重构后的事实 | 接入动作 |
| --- | --- | --- |
| 指南2.2：当前只有PC lv_conf、默认atomic spinlock | PC/STM32配置分离；板端缺mutex fail-stop | 使用config/stm32；必须注入FreeRTOS mutex |
| 指南2.2：可选LVGL自身RTOS锁 | 本轮冻结唯一UiTask，LV_OS_NONE | 不另建LVGL FreeRTOS锁方案 |
| 指南6 BACK双击：板端关闭BACK映射后自行gesture_update | services_sample_inputs已连接去抖后的BACK手势 | 默认直接sample_inputs，不再调用第二套gesture_update；set_key_map仅在明确改变产品映射时使用 |
| 指南6.1：BSP自行维护触摸双路径 | submit_touch统一缓存、semantic queue；input port创建pointer | BSP只提交一次校准数据，不手动按钮action |
| 原设备状态page setter：BSP另加队列 | submit_device_status五槽mailbox已提供 | worker走formal service；UiTask handler应用page |
| 指南字体：PC TinyTTF/完整TTF建议待隔离 | STM32已无TinyTTF强依赖，使用外部fonts注册 | BSP提供长期有效字库及动态中文fallback；静态子集不是全部POI字库 |
| 指南13.4：一般LVGL可在ISR调用flush_ready | 本项目合同更严格：ISR只通知，UiTask flush_wait后ready | BSP不要在DMA ISR调用LVGL；保留buffer所有权到完成 |
| 指南14/示例：BSP手动串接lv_init与app_init | ui_stm32_startup聚合原ports并一次app_init | BSP完成资源后UiTask调用正式startup；不能旧示例再调用一次app_init |
| 原清单25头文件/55结构/380声明行 | 新增runtime/display/startup及worker/触摸/device/catalog/capability包装 | 旧清单为基线；本目录当前清单含当前行号；差异CSV逐类型列出 |
| graph/tiles/cache类型原无CRC/解码workspace成员 | 4096/1024/4096 scratch已归caller-owned对象 | 依据新sizeof预算，禁止把旧结构大小用于栈/SDRAM布局 |
| demo、固定18km/h route replay、报告mock在公共源码 | 实现仅链接PC target | GNSS/navigation真实producer仍由BSP提供；STM32不能依赖PC replay symbol |
| 历史和preferences示例直接调用公共worker | 新增formal services worker包装与任务身份检查 | 板端worker优先调用包装器；不在UiTask执行存储worker |
| timeout/late ACK等靠分散getter观察 | get_diagnostics聚合；late_ack是unexpected ACK聚合 | 不将该值误解释成精确迟到分类计数 |

原 `docs/examples/ui_board_adapter_example.*` 保留兼容参考，不是本轮完整启动入口。它不能替代runtime/display/input注册，也不能绕开worker包装器在UiTask执行I/O。当前启动与调用顺序见03文档；member/signature的精确变化见 `接口结构变更.csv`。

本轮未重新选择硬件、分配原理图引脚或配置CubeMX，旧硬件核对结论不被源码refactor自动修复；FMC/LTDC等实际外设配置仍需BSP工程完成。
