最新视觉与交互以 [Navigation UI v2.0 Final](NAVIGATION_UI_V2_FINAL.md) 为准；本页保留通用后端接入说明。

本次交付是 LVGL 导航 UI、会话与异步数据接口、PC 演示适配和自动化验收。没有实现真实路径规划、偏航计算、GNSS 驱动、高德接入、蓝牙协议、地图文件解析或地图导入。这些功能由后续 STM32/ESP32/手机端提供。

## 页面与操作

| 场景 | 已实现的 UI 行为 |
| --- | --- |
| 尚未导航 | 导航中心显示定位状态；选择目的地、收藏路线、地图管理和手机导航入口；没有固定转向箭头或假 ETA |
| 目的地 | 后端提供的收藏地点、最近目的地列表，或在地图上选择中心点；不包含地址搜索引擎或中文键盘 |
| 路线准备 | 加载/规划中、取消、失败重试；旧请求的迟到回复不能覆盖新请求 |
| 预览 | 路线概览、起终点、有效距离和预计时间；只有后端 `start_allowed` 为真时提供开始操作 |
| 确认开始 | 等待匹配请求的成功 ACK 或有效权威会话更新；打开页面不等于开始导航 |
| 行中 | 分级灰色道路、黄色路线、比例尺、北向/航向、缩放、回中、操作菜单和有效指标 |
| 路口 | 使用后端转向点/阶段稳定缩放；用户浏览时自动相机停止接管；回中恢复跟随 |
| 指令 | 连续转弯、有效环岛出口、弱定位、偏航/重算失败、到达；缺失字段保留占位或提示，不生成出口编号 |
| 离页 | 会话继续；其他页面通过原有 P1 安全提醒显示转向；按照会话、路线版本、步骤和阶段去重 |
| 收藏路线 | 独立入口、有限列表与分页、预览、开始、删除确认；删除成功后当前预览失效 |
| 地图管理 | 区域列表、详情、版本、有效容量、可用/检查/更新/损坏状态、后端提供的进度、检查/更新请求、取消和失败反馈 |
| 到达与结束 | 到达页或结束确认；停止成功后回导航中心；导航停止不触发骑行保存或结束 |
| 恢复 | 后端提交 `RECOVERABLE` 后显示恢复入口；没有实现掉电存储 |

纯黑画布、中性灰卡片和黄色操作沿用现有设计。480×854 布局的内容底边为 838 px；底部操作为 y=766、72 px 高。FPS 浮层继续覆盖在顶层。PRTS 开机素材及流程保持原样。

## 实体输入与动效

- 列表和菜单：编码器旋转移动焦点，按压执行；返回先关闭内部页面或确认层。
- 行中地图：旋转缩放并进入浏览模式；跟随时按压打开菜单，浏览/总览时按压回中；菜单键及触摸菜单入口保持一致。
- 地图选点：左右/上下/缩放三个工具；页面键切换工具，编码器调整，按压切换至确认后执行；触摸可拖动地图或直接选择工具、确认。
- 保留返回长按/双击的骑行逻辑、电源、唤醒与触摸锁；导航菜单不覆盖骑行结束确认。
- 选点与地图手势支持取消；列表有限复用并保留焦点，返回不会隐式停止导航。
- 操作面板复用可打断弹簧。相机采用稳定缓动和通过路口后的短暂保持，不对整张地图做弹性旋转或大尺寸 ARGB 透明变换。

## 数据入口与调用顺序

1. STM32 首先注册原有 `ui_stm32_services_register()`，设置任务上下文的锁和现有系统服务。
2. 在 `ui_app_init()` 之前注册 `ui_stm32_services_register_navigation()`。导航 `dispatch` 与地图 `request` 回调只复制请求至工作队列，返回是否成功入队；不得在 UI 线程算路、访问 TF 或等待蓝牙。
3. 初始化 UI，再启动生产者任务。`ui_app_init()` 初始化邮箱并保留已注册的端口。
4. 工作任务回传结果、会话和地图窗口。只有 UI 线程处理结果并操作 LVGL。ISR 先通知任务，不直接调用这些提交入口。

可编译模板位于 `docs/examples/ui_navigation_adapter_example.h/.c`。它只连接请求队列，不实现硬件或模拟成功结果。

| 接口 | 用途 |
| --- | --- |
| `ui_stm32_services_complete_navigation(result)` | 对匹配请求回传路线、列表或开始/停止等操作 ACK |
| `ui_stm32_services_submit_nav_session(session)` | 权威会话、定位、来源、手机连接和可恢复状态 |
| `ui_stm32_services_submit_navigation(model)` | 速度、剩余距离、有效 ETA、定位/航向、当前步骤、阶段、转向点、下一步、环岛出口和重算状态 |
| `ui_stm32_services_submit_map_frame(frame)` | 经过请求及路线版本校验的可见道路/路线窗口 |
| `ui_nav_session_submit_catalog(catalog, revision)` | 可选的地图状态/进度或列表更新；生产者版本必须递增 |

地图/路线结果会复制进入固定邮箱，提交返回后调用方可复用自己的缓冲区；不会让 LVGL 保存工作任务临时内存指针。取消和超时使旧请求 ID 失效。开始/停止取消只取消 UI 等待及对应后端请求；实际状态以权威会话为准，后端仍需正确处理取消。

`session.version` 在提交时是生产者递增的快照序号；`get()` 返回的版本是 UI 观察版本，两者不要作为同一计数器使用。会话 ID 在来源之间保持唯一；活动会话须有非零路线 ID/版本。来源或活动路线变更会使旧操作结果、旧引导和旧提醒失效。停止成功后，旧会话不能被迟到的活动快照重新激活。

新引导生产者必须设置 `session_bound=true` 及匹配的 `session_id/route_id/route_revision`。`step_id` 表示步骤身份，距离变化不改变步骤 ID。各项数值的有效位单独设置；没有 ETA 不使用零点代替。定位和航向不是同一个有效位，低速或航向失效时不强制旋转地图。

经纬度使用 double；明确 WGS84 或 GCJ02，服务不替代坐标转换。一个地图窗口内道路、路线和目的地必须与 `origin.system` 一致；引导和地图也需由后端统一坐标系。`sampled_at_ms` 与 UI 单调时钟同源，`stale_after_ms` 是有效期，不能使用 UTC 秒直接填写。中心定位和行中引导分别提供有效期。生产接口中没有把 HDOP 当作米制精度。

## 地图 Provider 与资源边界

首版输入选择有限道路几何。最终 TF 地图文件格式仍由后端决定，工作任务把文件内容处理为道路段和路线窗口后提交；UI 没有宣称能直接读取 OSM/PBF/MVT/高德瓦片。

- `ui_nav_map_request_t` 包含请求 ID、路线 ID/版本、中心、坐标系、投影米/像素、航向、覆盖尺寸，以及跟随/概览/浏览/选点目的。`width/height` 表示按北向计算的覆盖矩形，在请求的米/像素下计量；行中请求已经计入相机缩放、旋转和边缘余量，不能把它当成显示帧缓冲尺寸。后端按这个范围取道路窗口，绘制仍使用 480×854 的页面视口。
- 一个 `ui_nav_map_frame_t` 最多 48 个道路段、64 个路线点、64 个建筑/绿地/水域凸区域和 12 个标签；道路级别 0/1/2 分别绘制主干、次级和支路。区域与标签的局部点相对 `origin`，单位米，东正北正。
- `NO_MAP` 结果仍可附带有效原点、比例和至少两个路线点，显示“仅路线、暂无底图”；不会丢弃可用路线，也不把路线几何当作底图已安装。
- 窗口是可见数据或简化概览，完整路线和道路网络保持在后端。长路线不能截取前 64 点当作整条路线概览。
- `destination_valid` 明确表示窗口中的终点。不能把窗口最后一点误标为目的地。
- 结果包括请求/路线/地图版本、坐标原点和比例。旧请求、旧路线版本、混合坐标系、超限数据和非法数值会被拒绝。
- 地图窗口请求超时为 5 s；导航请求默认 15 s，可在请求中设置。地图检查/更新等待默认 30 s；工作任务定期提交带匹配 `request_id` 的递增目录进度可延长等待，进度中断后仍会超时。繁忙时不反复重启地图请求，以便慢存储能够正常完成。
- 页面只绘制局部线段，不对大图层使用 LVGL transform。真实地图缺失时保留可用路线和明确提示；数据未更新不意味着地图已更新。

目前 PC 编译的窗口结构为 8624 B、会话 664 B、目录 2408 B，目录最多 8 行；相关邮箱按固定数量分配。导航工作区一次只构造当前页面，不创建整个城市的 LVGL 对象。实际静态内存、栈峰值与字体容量应以 STM32 链接映射和测量为准，PC 结构大小不是硬件总 RAM 用量。UI 刷新会复制数 KB 的快照，板端须预留足够 UI 任务栈并测量峰值。

作为屏幕缓冲预算的单独参考：480×854 RGB565 一帧为 819,840 B，双帧为 1,639,680 B；480×20 行的单个局部缓冲为 19,200 B。这些不包含地图/路线、LVGL 对象、字体缓存、其他任务和存储缓冲。PC 构建通过与 60 FPS 目标不能推导出 STM32 真机已经达到 60 FPS。

## 模拟器与验收

PC 演示适配器位于 `src/platform/pc/ui_pc_navigation.c`。路线为人工生成的转弯/连续路口/环岛场景，所有相关页面标明演示；坐标中心只用于测试投影，内容不是西安真实地图。真实地图更新返回未接入能力，不生成下载百分比或成功提示。

进入导航中心，选择演示地点，等待预览并明确开始。行中按 `n` 可依次测试接近、迫近、执行、连续转弯、环岛、重算失败、弱定位和到达。未开始会话时 `n` 不生成导航。STM32 服务默认关闭演示输入。

自动验收包含会话 ID/ACK、迟到结果、取消、超时/时钟回绕、停止失败、旧会话复活、地图版本与坐标系、几何上限、手动相机锁、无航向取景、连续同方向转弯去重，以及触摸/实体输入的完整页面流程。全帧与局部刷新分别执行现有工程回归并导出导航快照，检查字体、裁切和图层分配。

最新验证与预览见 [导航 UI v2 验收记录](NAVIGATION_UI_V2_VALIDATION.md)，首版记录保留在 [原导航 UI 验收记录](NAVIGATION_UI_VALIDATION.md)。

另修复了回归中发现的报告问题：存在距离、爬升或心率区间摘要时，骑行保存状态仍始终显示。

下一次真实数据验收需要一个有明确来源、坐标系和版本的小范围地图样包，以及配套路线和转向步骤。文件格式解析、算路/偏航重算和硬件性能优化属于后续后端工作，不在本次 UI 完成范围内。
