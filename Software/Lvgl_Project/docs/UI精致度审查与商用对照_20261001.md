## 判断：事实、推理和边界

**事实：**原截图的“骑行记录中”与时钟争用顶部空间；正文包含六个主要指标和八个扩展指标；大量亮色细线、相近字重和背景颗粒同时出现。原启动页是静态标签；原成就页只有六项累计门槛，确认操作没有详情。代码中原扩展数据还把所有心率区间的说明固定为“阈值区间”。

**设计判断：**当前主要缺口是信息层级、颜色语义、组件一致性和状态反馈。速度大字本身并不错误，但不能据此把所有指标都用同样重的视觉表达。更丰富的色彩与更夸张的动画不会自动带来成熟感。建议采用克制的骑行仪表界面，把更强的终端叙事用于启动、成就和骑行摘要。

**边界：**截图里的桌面任务栏覆盖了模拟器下端，不能据此认定真实 854 像素画面越界。PC 模拟器截图、虚拟时间动画和回归测试均不能证明 STM32 真机达到 60 FPS；字号、反光、视角、手套操作与高亮屏耗电仍需实际屏幕验证。本报告不是市场产品的全量功能评测。

## 彩色屏幕使用规范

按用户给定的 3 英寸有效显示对角线及 480×854 分辨率估算，像素间距约为 `76.2 / sqrt(480² + 854²) = 0.0778 mm/px`；48 px 约 3.7 mm，96 px 约 7.5 mm。实际值以有效显示区尺寸为准。[Google 官方触摸目标说明](https://support.google.com/accessibility/android/answer/7101858?hl=zh-Hans)给出的参考范围是 7–10 mm；Android 的 48dp 不能直接替换为 LVGL 的 48px。这个参考适合发现小热区，最终尺寸仍需结合骑行振动、触摸驱动、手套和实体键路径验证。

- 黑蓝底与白色读数保持主体可读性；黄色用于产品识别、当前焦点、确认与记录中状态。
- 心率、功率采用同一组 Z1–Z5 区间色：灰蓝、蓝、绿、橙、红；同时显示区间编号，不能只靠颜色传达含义。阈值沿用本次骑行实际配置，骑行中调整的新配置不回写当前会话。
- 状态胶囊：黄色记录中、橙色暂停、蓝色结束/保存处理中、红色存在待保存记录。文字仍是判断状态的主要依据；不能把“保存处理中”画成“保存成功”。
- 成就按骑行次数、距离、爬升、时间使用黄、蓝、橙、紫。颜色表示类别，解锁与进行中仍由文字、进度和条件区分。
- 暂未实现全局昼夜主题；上述颜色是当前暗色方案。日间对比度、配色个性化和色觉可达性需后续设计和实屏验收。

## PRTS 启发的原创设计范围

提取终端编号、工业分区、细线扫描、状态序列和克制的黄色强调，使用本项目的 BC / RIDE OS 标识。本轮未引入明日方舟的标识、角色图、原始启动素材或音频。

启动是有限演出，隐藏页面时停止刷新，减少动效设置下显示完成态。现在的扫描轨道是展示序列，**不是真实硬件加载百分比**。软件初始化前的耗时存储加载依然需要后续改为可观察的异步准备流程，才能把启动画面与真正的资源准备对应起来。

骑行中的终端感应来自结构和状态，不建议常驻扫描线、背景漂移、闪烁或弹跳数字。成就解锁、非骑行控制面板可以更有表现力；危急状态与错误提示优先直接出现。

## 动效规范与剩余差距

现有液体胶囊已经使用保持位置和速度的可打断弹簧；骑行状态采用更高阻尼，减少回弹。后续进一步细化应遵守：

1. 外壳先拉伸和展开，内容稍后进入；字体不拉伸、不模糊缩放。
2. 快速连续展开/收起时从当前状态继续，不能重置或跳回初始帧。
3. 触摸拖动跟手，取消手势只回到原状态；释放后有限回弹，不持续摆动。
4. 主读数保持固定锚点。平滑只用于显示，记录和告警判断继续使用原始有效数据。
5. 在相同条件下对比 30 与 60 FPS、分块与整屏刷新；检查峰值帧耗时、输入响应、内存和脏区域面积。60 FPS 的帧预算约 16.7 ms，30 FPS 约 33.3 ms，都是目标预算，不是本轮实测结果。

当前可打断弹簧和启动扫描并不等同于完整的液体融合渲染。真实液体轮廓、黏连桥、遮罩与大面积半透明会增加渲染成本；下一轮应先用少量原生几何验证视觉收益，再决定是否引入更复杂的绘制。

## 成就系统：本轮 16 项与后续能力

| 成长线 | 四级门槛 |
|---|---|
| 骑行次数 | 已保存 1 / 10 / 50 / 100 次 |
| 累计距离 | 100 / 500 / 1,000 / 5,000 km |
| 累计爬升 | 1,000 / 2,000 / 10,000 / 50,000 m |
| 累计记录时间（暂停不计入） | 5 / 50 / 100 / 500 h |

门槛属于当前产品设计选择，不是运动表现分级或医学结论。进度来自现有可持久化的终身累计量，不依赖内存中保留的最近 100 条详情。未保存、保存失败或仍在骑行中的会话不计入。

尚未实现：单次长距离、个人最佳、周/月目标、连续骑行、路线探索、历史解锁日期与一次性解锁通知。这些需要稳定的事件 ID、时区/日期规则及独立持久化数据。不能仅扫描最近 100 条记录就宣称终身个人最佳，也不能在每次打开页面时重复播放“新解锁”。建议优先增加单次距离和周目标，不把最高速度竞赛作为默认成长激励。
