# v1.1.2 RC 验收记录与后续路线

**开发成果可保存，发布验收未完成。** 当前 `VERSION` 仍为 `1.1.1`；分支为 `feature/ui-v1.1.2-finalization`。本记录不代表 `v1.1.2 RC` 或正式发布，也不授权创建发布标签。

| 项目 | 结果 | 证据与边界 |
| --- | --- | --- |
| 全新配置与构建 | 通过 | UCRT64 CMake `--fresh` 配置、255 步构建完成 |
| 自动回归 | 通过 | 23 项 CTest 连续 5 轮，115 次执行全部通过 |
| 控制中心几何与对象稳定性 | 通过 | 154～462 px 逐 7 px 采样、250 次状态更新、50 次形态往返；对象数量不增长、动画归零 |
| Simulator 启动存活 | 通过 | 本轮启动 15 秒未退出；这是存活冒烟，不是操作或性能测试 |

Phase 7G 是最新控制中心架构：一个 `ui_control_center` 对象，`CLOSED → COMPACT → EXPANDED`；Expanded 上滑直接关闭，声音/亮度在顶部 Inline Adjust。早期 Phase 7B～7F 报告的双层 Overlay 和 Bottom CONTROL 描述仅作历史记录。

## RC 前阻断项

1. 可见 Simulator 完整走通 Home、预骑行/GPS、Dashboard、四张 Dynamic Card、导航、暂停/恢复、结束保存、Summary、History；分别测试鼠标拖拽、Encoder、返回键。
2. 控制中心验证首次下拉、再次展开、Expanded 上滑直接关闭、横向滑条轴锁、Focus 与回弹、P0/P1 抢占和恢复。
3. 提供可重复的 PC 故障入口并验证失败、超时、拒绝、低电量、传感器丢失、存储错误；确认顶部/底部反馈不重复。
4. 用独立 Debug 配置开启必要监控，进行至少 30 分钟混合操作，记录 FPS、Handler Busy、Heap/Peak、对象、Timer、Animation 的起点/峰值/终点，无持续增长、`No memory` 或持续帧率下降。
5. 重新核对界面文字、长 WiFi 名称、状态栏、导航交互坞和保存后历史；修复验收中发现的问题并复跑自动测试。

阻断项完成后再更新 `VERSION`、系统页版本文案、README/CHANGELOG，提交发布改动并创建 `v1.1.2` 标签；检查远端同步是否符合仓库分支策略。Hardware 下未跟踪 BOM/Gerber/PickAndPlace 文件不属于 UI 提交。

## 发布之后的开发路线

1. **STM32 基础显示 Bring-up**：CubeMX、Clock/MPU/Cache、FMC SDRAM、LTDC、DMA2D、LVGL Port；先证实 RGB565 帧缓冲、局部刷新与内存预算。
2. **输入与任务边界**：Touch、Encoder、实体按键映射为现有 `UI_INPUT_*`；FreeRTOS UI 线程独占 LVGL，验证连续操作与抢占。
3. **设备服务**：GNSS、气压计、骑行引擎、BLE 传感器、ESP32-S3、TF/FatFs、音频；复用 App State/Command Service 契约并验证掉电保存。
4. **真实内容**：地图瓦片/路径和 TF 资源加载需在显示、存储与定位稳定后开展；音乐/天气接入真实后端。个人主页目前为 Legacy，成就入口未完成，另立需求与版本，不作为 v1.1.2 已交付功能。

真实地图和 STM32 驱动不应为了赶 v1.1.2 标签混入当前 UI 发布提交。
