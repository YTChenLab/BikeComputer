# BikeComputer UI v1.3.0 Ride Report 实现报告

## 1. 版本目标

v1.3.0 将原先分离的“骑行总结”与“历史骑行详情”收敛为统一的“骑行报告 / RIDE REPORT”。两个入口共享同一套 LVGL 对象树生成逻辑，仅数据来源、返回目标和 Summary 完成按钮不同。

参考图中的 `01/04 ~ 04/04` 被理解为设计内容分组，产品实现为一张连续纵向滚动页，不设计为四张互相割裂的横向页面。

## 2. 界面结构

固定区域：

- 统一状态栏；
- 返回操作；
- `骑行报告 / RIDE REPORT` 标题。

纵向滚动区域：

1. Mock 路线预览、起终点、指北与比例尺；
2. 骑行类型和完成时间；
3. 距离 Hero，并列显示时长、平均/最高速度和累计爬升；
4. 骑行表现指标矩阵；
5. 速度趋势；
6. 可选心率趋势与心率区间；
7. 可选功率、踏频趋势与功率区间；
8. 海拔趋势及爬升/下降聚合；
9. 能量与环境；
10. 由长距离、爬升和有氧区间阈值产生的规则化总结；
11. Summary 模式的完成按钮。

## 3. 数据与存储

- `ui_ride_report_model` 是 Summary/Detail 的统一展示模型。
- 速度、心率、功率、踏频和海拔最多保存 120 个抽样点，满容量时紧凑采样，不把原始高频数据直接塞入 LVGL Chart。
- 历史文件格式升级为 v2，写入新聚合值、能力标志、趋势和区间。
- PC 存储层仍能读取 v1 记录；旧记录不存在的趋势不伪造，显示 `NO TRACE DATA` 或根据能力标志隐藏整段。
- 提供完整、无功率、无心率/踏频、短途、长距离爬升 5 组确定性 PC Mock。

## 4. 交互逻辑

- 鼠标左键在报告内按下并拖动：模拟触摸纵向滚动。
- 鼠标滚轮/键盘方向键：转换为 Encoder 语义输入，每次按 260 px 内容块平滑滚动。
- 滚动目标根据当前内容高度计算并限制在有效区间，快速连续输入不会越过页尾。
- Summary 模式 `Enter`/完成按钮回到 Home；Detail 模式返回 History。
- 报告视口拥有内部垂直手势，不把本次拖动交给全局控制中心/页面手势。

## 5. 内存策略

- 不使用整屏 ARGB 透明动画层。
- 趋势由 LVGL Chart 和有限抽样点组成。
- Summary/Detail 页面可以同时保留数据模型，但只在活动时创建长内容对象。
- 页面离开时取消动画并清理内容对象，重新进入时由模型重建。

## 6. 验收结果

- UCRT64 Debug 完整构建：通过。
- CTest：`26/26` 通过。
- MiSans 字体覆盖：`462 glyphs / 463 required codepoints`。
- 离屏像素预览：已检查首屏、趋势/区间中段和能量/总结页尾。
- 渲染日志：测试将 `No memory`、`Allocating layer buffer failed` 和 `glyph dsc. not found` 视为失败，本次未触发。
- 可选区段：无功率和无心率/踏频情形的内容高度均小于完整情形，证明已重排而非空占位。

## 7. 能力边界

本版本完成的是 LVGL UI、交互、报告模型、PC Mock 和 PC 历史持久化。以下项目不能因为页面已显示而视为完成：

- 真实 GNSS 轨迹和地图瓦片/矢量地图引擎；
- STM32 传感器数据接入；
- TF 卡 FatFs 历史文件后端；
- GPX/FIT 导入导出；
- 真机 SDRAM/LTDC 峰值内存、帧率和掉电测试。

当前路线图是与未来地图 Provider 解耦的 LVGL Mock 几何预览，不是西安实景地图。
