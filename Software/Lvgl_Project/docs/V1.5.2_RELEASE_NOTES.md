# BikeComputer LVGL UI v1.5.2 版本更新日志

- 发布日期：2026-10-10（Asia/Shanghai）。
- 上一版本：v1.5.1；本次本地源码比较基线：`fd1db03db101cee2306c9829d153a090046239a0`。
- 范围：`Software/Lvgl_Project` 的源码、构建配置、测试、适配与接入资料，以及仓库首页的软件版本入口。未纳入 STM32 固件、硬件或结构设计文件。
- 内置 LVGL 仍为 `9.3.0-dev`，画布仍为 480×854、RGB565。v1.5.2 是软件适配归档版本，不是整机验收版本。

## 1. PC 与 STM32 共用源码，构建目标分开

原先集中在单个 CMake 文件的配置拆为公共源清单、PC 构建和 STM32 构建。`UI_PLATFORM=PC` 生成 Windows 模拟器；`UI_PLATFORM=STM32` 生成无 HAL 依赖的 `bike_ui_stm32` 静态库。`config/pc/lv_conf.h` 与 `config/stm32/lv_conf.h` 分别控制桌面和板端能力，根 `lv_conf.h` 保留 PC 兼容入口。

新增 Arm Compiler 6／Cortex-M7 工具链和 host 契约测试目标。STM32 清单排除 PC HAL、SDL／Windows 端口、桌面文件系统、演示和测试代码；FreeRTOS 由真正的板端工程提供，不把 PC POSIX port 移到板端。

GitHub Actions 沿用现有 PC 构建、回归及发布流程；STM32 host 和 ARM 编译在本地完成验证。Windows 发布包同步包含当前 STM32 接入说明及历史参考资料。

发布前修复 LVGL TLSF 对 AC6 的编译器识别：采用该编译器支持的 builtin 位运算路径，消除错误落到旧 ARMCC 分支后的未声明／未解析 `__clz`。GCC 仍走原路径；静态库及 ARM 符号审计重新验证。

PC 的背景、并发、日期、演示骑行与报告、天气默认值、输入和路线回放移到 `src/platform/pc`。共用 UI 和服务通过内部平台边界调用，不再要求板端引入 PC 后台或假数据。页面布局、导航算法和地图覆盖不在本版重新设计。

## 2. STM32 启动、显示、线程与内存接口

- `ui_stm32_startup_t` 汇总运行上下文、资源 readiness、显示、业务服务、历史、配置、导航、地图、搜索、设备、字体、声音及 raster 缓冲区；UiTask 在 BSP 资源就绪后调用 `ui_stm32_startup()`。
- `ui_stm32_ui_task_handler()` 管理 LVGL handler 和诊断；`ui_runtime_port_t` 提供单调时钟、UiTask／ISR 判定及故障回调。初始化只执行一次，部分初始化失败需要复位。
- LVGL 9 PARTIAL 显示端口验证独立且对齐的缓冲区，区分同步完成、DMA 异步完成和失败。ISR 只通知任务，UiTask 确认 DMA 释放像素后完成刷新。
- 触摸任务提交校准后的坐标缓存；pointer indev 由 UiTask 创建和读取，生产者不调用 LVGL。
- 更新服务邮箱、导航／地图／搜索、历史与配置 worker 的边界；后端提交命令只排队，完成结果按 command/request id 匹配，拒绝错误上下文和无效数据。
- 大对象使用 32 字节对齐的 `.ui_sdram` 约定，大型解析／规划工作区从栈移出或使用显式工作区。此源码约定不会自动初始化 SDRAM，也不能替代实际链接脚本、MPU、D-cache 和 DMA 测试。

## 3. 实体输入契约升级

GPIO／编码器四相采样、消抖、单击、双击和长按识别归 STM32 InputService。系统队列复制标准的 12 字节 `ui_physical_input_event_t`，UiTask 调用 `ui_stm32_services_handle_input_event()` 消费已经识别的事件。UI 不再维护第二套手势时序或 GPIO 采样逻辑。

`key/action` 为固定宽度字段，`reserved=0`；编码器 delta 范围为 -64..64，超限记录失败，生产者需要拆分批次。时间戳使用系统统一单调毫秒时钟，不作为 UI 重新判断单双击的依据。结构是进程内队列记录，不是无线协议。

移除旧 `ui_stm32_services_sample_inputs()`、`ui_stm32_services_set_key_map()`、`ui_stm32_services_submit_input()`，以及 `ui_hardware_input`、`ui_back_key_gesture` 和旧识别测试。PC SDL 将相同语义事件复制到原输入队列，保持触摸输入；F5／F6 可注入 BACK 双击／长按进行联调。

实体 POWER 由 PowerService 处理，UiTask 通过 `ui_stm32_services_apply_display_state()` 应用状态通知。STM32 项目的 InputService／PowerService 驱动和旧 `type/value` 队列 payload 升级尚未实现，不属于本版提交范围。

GCC host 和 AC6 目标仍有存量缩进、字段初始化、参数等编译警告，本版不宣称板端零警告。host 的一个 1104 字节栈帧告警属于 64 位 host 编译结果，不能直接当作 Cortex-M7 的实际栈占用；实际任务栈、水位、并发和内存仍需板端验收。

Windows 包生成、CRC／SHA-256、附件内容和脱离工具链 PATH 的启动检查已在提交前完成；云端 Actions 会针对发布提交再次构建和测试，云端状态以实际运行结果为准。

主要复现命令（在 LVGL 工程目录，使用已存在的工具链）：

```sh
cmake --preset bike-ui-ucrt64 -B build/release-v1.5.2-pc -DBUILD_TESTING=ON -DUI_REGENERATE_FONTS=OFF -DPython3_EXECUTABLE="<已有 Python 解释器>"
cmake --build build/release-v1.5.2-pc --parallel 4
ctest --test-dir build/release-v1.5.2-pc --output-on-failure
cmake --preset bike-ui-stm32-host -B build/release-v1.5.2-stm32-host
cmake --build build/release-v1.5.2-stm32-host --parallel 4
ctest --test-dir build/release-v1.5.2-stm32-host --output-on-failure
```

ARM 构建参数见当前接入说明；发布包使用 `tools/package_windows_release.py`，不加入 runtime 或本机安装包。

## 6. 沿用数据与待完成内容

四个主要地图资源沿用 v1.5.1 的底图、彩色瓦片、骑行图和地点索引，未扩大覆盖；导航来源 ZIP、字体与许可保留原数据。位置仍使用 PC 路线回放，不能视为真实 GNSS。

STM32 尚需完成实际 BSP／HAL、FMC SDRAM、LTDC／DMA2D／触摸、SDMMC／FatFs、InputService／PowerService、传感器与 ESP32 协议、链接布局和 Cache 一致性，再进行完整固件链接和实板压力测试。host 契约测试和 ARM 静态库编译只验证软件边界，不证明整机可运行。

地图仍受 OSM 完整性和入口／道路连通性限制；联网地点补充仍需要有效 Key 与真实样本验证。发布包保持联网关闭、空 Key 模板，不包含个人 Key、运行存档、安装包和构建缓存。
