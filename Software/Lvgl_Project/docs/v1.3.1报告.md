### 2.2 本次发现并修复的问题

验收首次执行 `cmake --build build --target main --clean-first` 时，发现主程序链接失败：

```text
undefined reference to ui_font_misans_ui_20
undefined reference to ui_font_misans_metric_60
undefined reference to ui_font_misans_num_68
```

根因不是字体内容缺失，而是 `clean-first` 会先删除生成字体源；原 CMake 配置中只有部分生成字体被固定加入 `main`，其余字体是否进入目标依赖于配置时文件是否已经存在。这会造成普通增量构建成功、全新或清理构建失败。

修复方式：

- 将全部运行时生成字体从条件性 `GLOB` 结果中排除；
- 将 7 个生成字体源作为 `MAIN_SOURCES` 的固定成员显式声明；
- 保留字体生成目标和字符覆盖测试；
- 重新执行干净构建、完整构建和全量测试。

修复后干净构建可稳定重现，MiSans 运行时子集为 462 glyphs / 463 required codepoints。

## 3. 全局 UI 设计规范

### 3.1 视觉语言

- 纯黑主背景，深灰 Surface，白色主文字，灰色辅助信息，黄色作为唯一主强调色；
- 继续使用 MiSans 字体体系，数字、单位、正文和状态信息按用途拆分字体；
- 使用细描边、小圆角和高信息密度布局，保持公路车码表与工业设备感；
- 不使用手机 App 式大面积白色卡片，不使用多个互相覆盖的半透明页面；
- 页面切换后均保持独立不透明背景，不把 Dashboard 内容误当成全局背景；
- 动画优先作用于位置、尺寸、局部缩放和颜色，避免生成大尺寸透明图层缓冲。

### 3.2 固定与冻结区域

Dashboard 下列区域继续冻结，v1.3.1 未重构其尺寸比例：

- 顶部状态栏；
- 实时速度区域；
- 黄色速度条；
- 2×3 核心骑行数据区；
- 当前背景资源；
- MiSans 视觉比例。

### 3.3 全局状态栏

所有正式页面共用 App State 驱动的状态信息：

- 卫星数量；
- 当前时间；
- WiFi 状态；
- Bluetooth 状态；
- 电池百分比与电池图标。

状态栏注册容量为 16，能够覆盖当前页面集合；自动测试包含 12 个并存实例回归，避免新增页面后静默注册失败。

### 3.4 Bottom Interaction Surface

底部只允许存在一个统一视觉容器：

```text
Bottom Interaction Surface
├─ Dynamic Card Mode
└─ Interaction Mode
```

设计原则：

- 内容变，不换容器；
- 状态变，不叠弹窗；
- Interaction 事件抢占时原位替换 Dynamic Card；
- 事件结束后恢复此前 Card 和状态；
- Mini、Normal、Expanded 共用几何、背景、圆角和动画 Token；
- 产品代码中没有 `lv_msgbox` 弹窗残留。

Home 的 7 个 Encoder 焦点按视觉从上到下统一排序：

1. 用户身份卡 → Profile；
2. 开始骑行；
3. 开始导航；
4. 最近骑行记录；
5. 历史记录；
6. 我的成就；

Touch 点击整张功能卡均可触发，不要求点击小文字或小图标。Home 累计数据、Profile、Achievements 和 History 使用同一份持久化历史真值，不显示互相矛盾的固定演示数字。

## 6. 骑行状态与返回键逻辑

### 6.1 骑行流程

```text
Home
→ 请求开始骑行
→ Command Pending / Success / Failed
→ Riding
→ Auto Pause 或 Manual Pause
→ Resume
→ 长按 Back 请求结束
→ Confirm YES / NO
→ YES：完成、保存、Ride Report
→ NO：恢复结束前的 Bottom Surface 内容
```

所有状态变化刷新统一 Bottom Interaction Surface，不建立第二个独立弹窗。

### 6.2 Back 语义

| 输入 | 骑行中行为 | 非骑行行为 |
| --- | --- | --- |
| 单击右键 / `Esc` / `Backspace` | 普通返回，不结束骑行 | 返回上一级 |
| 双击 | 手动暂停；再次双击恢复 | 不执行骑行状态变更 |
| 长按约 1.2 秒 | 打开结束骑行确认 | 不触发错误结束流程 |

为区分单击和双击，单击释放后约 280 ms 才提交返回事件。

### 6.3 自动暂停

Simulator 使用 `S` 切换移动/停止状态：

- 停止约 3 秒后自动暂停；
- 恢复移动约 1 秒后自动恢复；
- 自动暂停与双击手动暂停经统一骑行状态机处理。

以上仅是 PC 数据源模拟，真机速度阈值、传感器抖动和时间参数仍需在 STM32 阶段标定。

## 7. Dynamic Card Dock

Dynamic Card 是 Dashboard 底部的 Normal Content Mode，由四张独立 LVGL Card 构成：

1. Extended Ride Data：平均/最大速度、海拔、累计爬升、卡路里、温度、心率区间、圈数；
2. Navigation：转向距离、道路名、剩余里程、剩余爬升、ETA 和方向；
3. Music：上一首、播放/暂停、下一首、播放模式；
4. Weather：温度、天气状态、骑行建议、风速、降雨概率、AQI。

交互规则：

- Viewport 只允许纵向滚动，Card 高度一致、间距为 0；
- 使用 LVGL Scroll Snap，一次最多切换一张；
- 左侧 Indicator 固定在 Scroll Content 外；
- Touch Down 在 Dock 内后，本次序列从 PRESS 到 RELEASE 始终归 Dock；
- Touch 和 Encoder 共用唯一 `active_card`；
- Encoder Browser 旋转切卡，Press 进入 Control；
- Control 初始为 Neutral Focus，Rotate 后才选择具体控件；
- Back 随时退出 Control 返回 Browser。

Music Card 的控制顺序严格为：

```text
上一首
播放 / 暂停
下一首
播放模式
```

Touch 点击整项可执行，按压采用局部缩放回弹；播放模式在顺序播放、单曲循环、随机播放之间循环。UI 只提交媒体语义命令，当前没有真实音频后端。

## 8. Interaction Dock 与事件抢占

Interaction Mode 支持 6 类内容：

- INFO；
- ACTION；
- CONFIRM；
- CONTROL；
- NAVIGATION；
- MEDIA。

统一能力：

- `show`、`hide`、`update`、`replace`；
- Priority Override；
- Restore Stack；
- 主/次操作；
- 数值增减、切换与提交；
- Pending、Success、Failed、Timeout、Rejected 状态反馈。

高优先级骑行安全或关键系统事件可抢占当前 Card；事件结束后恢复原 Dynamic Card，不显示“Dynamic Card + 独立小 Popup”的双层 UI。

## 9. 控制中心

控制中心为统一的两段式 System Control Surface，而不是两套页面：

```text
CLOSED → COMPACT → EXPANDED → CLOSED
```

- 页面顶部第一次下滑打开 Compact；
- 继续下滑时同一 Surface 平滑 Morph 到 Expanded；
- Compact 上滑关闭；
- Expanded 上滑直接关闭，不先退回 Compact；
- 下边缘使用圆角和居中位置条表达可拖动状态；
- WiFi、Bluetooth、GNSS、省电模式支持整框 Touch；
- 声音与亮度在 Expanded 内直接 Inline Adjust，不再呼出底部 CONTROL；
- 滚轮/方向键循环选择控件，`Enter` 执行；
- 调节项以 5% 步进变化，`Enter` 或 Back 提交并留在控制中心；
- `M` 可按“关闭 → Compact → Expanded → 关闭”循环，便于 Simulator 验证。

控制中心使用 Focus Capsule、磁吸移动、按压回弹、Pending Pulse 与局部滑条动画。拖动过程中只更新几何，避免重复启动动画造成抖动。

Navigation V2 包含：

- 500 px 地图视觉区域；
- 路线、当前位置、缩放与定位状态；
- 92 px 的 1×3 数据条；
- 大号粗体黄色方向箭头；

## 11. 骑行报告 UI 与交互

Summary 和历史 Detail 共享同一套 Ride Report 对象树，仅入口、数据来源和结束行为不同。

页面顺序：

1. 路线预览、起终点、指北和比例尺；
2. 骑行类型与完成时间；
3. 距离 Hero、时长、平均/最高速度、累计爬升；
4. 平均心率、平均功率、平均踏频、热量、最高海拔、总下降；
5. 速度趋势；
6. 可选心率趋势与心率区间；
7. 可选功率/踏频趋势与功率区间；
8. 海拔趋势与爬升/下降；
9. 能量、运动时间、环境与补水建议；
10. 长距离、爬升、有氧耐力等规则化总结；
11. Summary 模式的完成操作。

交互：

- 鼠标左键按住纵向拖动；
- 鼠标滚轮/方向键按约 260 px 内容块平滑滚动；
- 滚动目标根据实际内容高度限制，不越过首尾；
- Summary 完成后返回 Home；
- Detail 的 Back 返回 History；
- 报告视口拥有本次纵向手势，不误拉出控制中心。

内存策略：趋势最多保留 120 个抽样点，页面离开时清理长内容对象，重新进入时从模型重建；传感器能力缺失时整段回流，不制造假数据占位。

## 12. 数据、命令与持久化

### 12.1 单一状态来源

- `ui_app_state`：路由、骑行、状态栏、连接、控制、媒体和导航状态；
- `ui_router`：页面历史和生命周期；
- `ui_command_service`：异步命令与结果；
- `ui_state_adapter` / `ui_navigation_service` / `ui_input_queue`：平台数据进入 UI 线程；
- `ui_bottom_surface`：底部唯一视觉容器。

页面不直接依赖 SDL；PC Mouse、Keyboard 和 Wheel 先转换为 `UI_INPUT_*`。未来 STM32 GPIO、Touch 与 Encoder 只需产生相同语义事件。

### 12.2 PC 持久化

- 保存路径：`runtime/ride_history.dat`；
- 最多保存最近 100 条，History 页面展示最近 50 条；
- 使用版本化格式、CRC32、临时文件替换和备份恢复；
- 当前写入格式为 v2，并保留 v1 记录只读兼容；
- Home、Profile、Achievements、History 和 Ride Report 共用同一历史 Repository。

### 12.3 Mock 边界

PC 服务提供骑行、天气、导航、连接、媒体和硬件命令 Mock，用于验证 UI 闭环。Mock 成功不代表真实设备已经完成，报告和页面对这一区别不作模糊表述。

## 14. 手势所有权

为避免多次点击后页面穿透、控制中心误触和滚动冲突，手势从 PRESS 到 RELEASE 全程锁定给起点所属区域：

- Dynamic Card Viewport；
- Navigation Map；
- Bottom Interaction Surface；
- Ride Report 长页；
- History、Achievements、Settings、System 等列表；
- 控制中心自身。

只有 Touch Down 起点不属于以上内部滚动/控制区域时，全局上下滑和横向换页才可接管。

## 17. 未完成边界与风险

以下内容不能因为 Simulator UI 已完成而判定为完成：

- 真实 GNSS、道路匹配、偏航重规划；
- 西安地图瓦片/矢量数据、坐标投影、TF 索引和 Tile Cache；
- BLE 心率、功率、踏频传感器；
- STM32 Touch、Encoder、按键、LTDC、SDRAM、DMA2D 驱动；
- TF/FatFs 历史存储、拔卡、断电和文件损坏恢复；
- GPX/FIT 导入导出；
- 真实媒体控制、音频播放、联网天气；
- STM32 帧率、CPU、堆峰值、栈深度、总线带宽和长时稳定性。

主要风险不是当前 UI 路由，而是后续真实数据速率、地图内存、SDRAM 带宽和存储掉电一致性。STM32 接入时应复用现有语义接口，避免硬件任务直接调用 LVGL 或页面函数。
