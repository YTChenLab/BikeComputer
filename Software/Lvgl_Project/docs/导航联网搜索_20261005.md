# 搜索重置与联网补充（v1.5.1，2026-10-05）

本阶段以 v1.5.0 为基础改进搜索，现纳入 v1.5.1。按用户要求，本版仅预留联网接口，默认关闭，不读取个人 Key；实际启用与真实地点联调暂缓。最终发布验收见 [v1.5.1 发布记录](V1.5.1_RELEASE_NOTES.md)。

## 当前已完成

- 每次打开导航搜索清空旧关键词、候选、选中条目与字母拨盘。取消旧查询，拒绝其晚到结果；快速重开以及从目的地或路线预览返回搜索采用同样行为。在同一个搜索面板内从结果焦点返回输入仍保留正在输入的关键词。
- 原有离线地点与骑行图继续可用，数据资源未重新替换。Windows PC 端增加可选高德输入提示请求，与当前离线候选交替合并、去重，最多八条并提示溢出。联网失败保留离线候选，不把失败响应解析成目的地。
- 请求固定通过 HTTPS 发往 `restapi.amap.com`，限制西安市；根据返回区县编码过滤到新城、碑林、莲湖、灞桥、未央、雁塔、长安，并检查落点在现有资源范围内。不包含临潼、咸阳或高新区跨范围托管片区。
- 无 POI ID、无有效坐标、范围外或非法坐标的建议被跳过。同名且相近的离线/在线结果去重，不依据名称把异地同名目标合成一个点。候选显示“高德”及返回的所在区、地址。
- 网络调用在存储工作线程内进行，UI 不执行 HTTP 或文件读取；使用阶段超时、查询过期检查和 64 KiB 响应上限。服务仍保留 5 秒 UI 请求超时。Windows 系统原生 WinHTTP 提供网络请求，无新增运行环境或第三方依赖。
- 联网查询词、响应和密钥不写日志，不把高德地点批量抓取或加入离线地点文件。密钥通过本机运行时文件读取，不进入源代码、Git 或预览包。程序内也没有保存搜索历史的功能。

## 后续本机启用步骤（本版暂缓）

1. 在[高德开放平台](https://console.amap.com/)创建 Web 服务类型 Key，并确认账号已开通[输入提示接口](https://lbs.amap.com/api/webservice/guide/api-advanced/inputtips)权限及适用额度。不同 Key 类型不可互换。
2. 将项目里的 `config/navigation-online.example.ini` 复制到项目根目录下 `runtime/navigation-online.ini`，在本机填写 `amap_key`，把 `enabled` 改为 `1`。不需要把密钥发到聊天或提交到 Git。
3. 重启模拟器。没有该文件或 `enabled=0` 时继续纯离线搜索；已开启但配置无效时，不发出网络请求。没有离线结果且联网失败时，搜索栏分别显示“密钥无效”“联网失败”或“联网超时”。
4. 用确实缺失的小区全名、全拼和缩写分别检查返回候选、地址、地图位置和规划终点。只有真实 Key 下的查询结果可以证明接口对这些输入的支持，合成测试不能代替。

程序也接受已有进程环境里的 `BIKE_NAV_ONLINE_CONFIG` 作为独立配置文件路径；本轮未修改系统环境变量。`runtime/` 已在 `.gitignore` 中排除，打包工具只加入空模板。

## 坐标、字体与导航边界

高德返回的坐标属于 GCJ-02，当前 OSM 地图与骑行图使用 WGS84。代码采用迭代近似逆算后再放到地图，不直接混用两种坐标；这不是官方精确逆转换，也没有校门实地误差验收。目的地页明确显示“联网坐标 · 请确认落点”，需要用户确认或手动调整到可通行位置。高德输入提示返回的是中心点，不代表大门或骑行入口。

联网只补充地点查询，不把当前 OSM 骑行图变成高德骑行引擎。找到地点仍可能因为地图缺路、入口私有、吸附距离过大而无法规划；不得以直线冒充可骑行路线。

PC 端启用有效联网配置时，加载项目已有 MiSans-Semibold TTF，为 20/24 px 内置字体补充缺字；使用 TinyTTF 和小缓存，不另安装字体库。完整 TTF 约 7.66 MiB，由 PC 堆保留至进程结束；响应缓冲上限 64 KiB，JSON token 数组在 PC 上约占 48 KiB 栈，不能直接当成 STM32 内存预算。板端需通过现有搜索服务端口接入手机/网络代理，并独立适配中文外存字库及密钥管理。

当前拨盘仍为 A–Z。联网服务是否支持所有中文全拼或首字母，官方文档没有作出普遍保证；必须用具体小区样本实测。如果服务对缩写无结果，应使用全名输入来源或手机伴随端，不能凭缩写猜造目的地。

## 验收与尚缺信息

v1.5.1 发布核查另修复 TinyTTF 正常缺字回退被误报为缓存失败的问题，并保留原有英文字体回退。实际缓存分配失败仍报告错误；新增缺字替换后继续显示中文以及英文字体解析回归。

已完成首轮 44 项 CTest，全通过（223.59 秒），包含搜索重置、旧请求拒绝、完整/分块地图实际集成，以及联网 JSON/UTF-8、七区过滤、非法坐标、合并去重、配置和断网回退逻辑。随后补充动态字体和联网确认页，9 项补充回归全部通过（218.53 秒），包含完整及分块实际地图流程。最后增加配置 BOM、严格 JSON 数字、原生网络错误分类，以及选择联网候选显示落点确认、返回即清空的应用流程后，6 项针对性检查全部通过（8.50 秒）。最终编译无错误或警告。

Windows 原生 HTTPS 通道已用无效占位 Key 核验，高德真实接口返回密钥错误，程序正确识别为 `UI_PLACE_ONLINE_KEY_ERROR`，未读取用户真实密钥。这验证了网络通道和错误响应处理，不证明有效地点查询效果。

用户已表示有 Key，随后决定暂时预留接口；本版不要求提供密钥路径，具体搜不到的小区样本仍待后续验收。因而没有真实地点查询验收，不能宣称已达到手机 App 的地点覆盖或任意缩写都可找到。后续至少需要实际小区样本、有效接口权限，以及真实骑行终点/入口核验。当前离线库包含 2,265 条“住宅”分类记录，含公寓与住宅区域，不能按独立小区数量解释。

## 官方依据

- [高德输入提示 API](https://lbs.amap.com/api/webservice/guide/api-advanced/inputtips)：Web 服务 Key、城市限制、POI ID、区县编码、坐标和地址字段。
- [高德坐标转换](https://lbs.amap.com/api/webservice/guide/api/convert)：官方接口转换至高德坐标，不提供本项目所需的官方 WGS84 逆算接口。
- [高德开放平台服务协议](https://lbs.amap.com/pages/terms/)：按已开通服务及账号授权使用，本轮不实现批量离线抓取和数据库镜像。
- [WinHTTP 超时接口](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpsettimeouts)：在请求句柄上设置解析、连接、发送和接收超时。
