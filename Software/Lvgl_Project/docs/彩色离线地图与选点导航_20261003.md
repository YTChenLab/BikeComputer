# 彩色离线地图与选点导航（2026-10-03）

本轮完成 PC 软件与共享地图核心：彩色离线地图、多级清晰度、后台读取、缓存、地图选点、道路图实时规划、引导回放。地图卡片仍为 464×540，交互坞仍为 464×226，底边 y=838。TF 容量充足并不等于绘制带宽和工作内存无限；地图按视野读取，UI 不做文件读取或寻路。

## 使用方式

1. 首页进入导航，长按地图中的位置，交互坞显示所选位置的经纬度。
2. 点击“规划路线”，后台根据当前位置与选点计算道路路线；完成后显示路线预览。
3. 点击“开始导航”。地图、路口相机、距离和下一步转向来自实际规划结果。
4. 硬件返回键（PC 右键/返回映射）打开快捷操作，再选择“结束导航”并确认。
5. 也可点击待机交互坞上部“选择目的地”区域，移动地图让目标进入中央准星，再点“选这里”。编码器进入地图卡片后，轮转到准星并按压可选择中央位置。
6. “我的路线”“最近使用”继续可用。所选新路线 ID 为 2，与预装路线 ID 1 分开。

导航过程中长按地图不会修改目的地。需要先结束当前导航，再选择新目的地。规划被取消或返回时，过期请求结果不会进入新会话。

PC 位置来自沿道路路线的 REPLAY 回放，当前速度按 18 km/h 生成。它验证显示和交互，不是实际 GNSS。真机接入后必须提交真实时间戳、位置质量、匹配进度和航向。

## 缓存与动画

- PC 有 24 个 RGB565 瓦片槽位和两块 768×768 底图缓冲，均在 LVGL 通用对象堆之外分配。
- 地图先显示已完成的一帧，后台读取新视野；普通平移、航向变化可复用缓存。
- 后台只写空闲缓冲，UI 在绘制周期之间采用 READY 缓冲，DISPLAY 缓冲保持只读。
- 编码器、触摸拖动、液体胶囊和文件读取相互独立。地图请求最多每 140 ms 检查一次，视野基本不变时不提交新请求。
- 跨清晰度层切换时按实际地图比例调整坐标，并继续尚未完成的缩放动效；缩小时选用能够覆盖旋转后视口的瓦片层。
- 路线预览支持继续拖动和缩放，不再每次后台刷新都强制回到路线总览。
- 手指按住地图时停止自动相机，避免长按目标漂移。图层更新保持原来所看的世界位置。
- Debug 构建保留断言和调试符号，通过 `UI_PC_FAST_MAP_RENDERING` 对 LVGL 软件绘制和地图核心启用 `-O2`，没有通过关闭检查来提高帧率。

瓦片编码支持 RGB565 原始数据、游程编码和 [LZ4 原始块](https://github.com/lz4/lz4/blob/dev/doc/lz4_Block_format.md)。C 解码器使用有界输入与输出，校验长度、偏移、版本、坐标、索引和 CRC。运行端不依赖 Pillow、NumPy 或 LZ4 DLL；制图工具使用电脑已有依赖，本轮没有安装软件包。

## 道路规划能力与边界

道路图包含 126,839 个节点、213,156 条有向边、2,132 个路名。A* 在后台执行，工作区由调用者提供；依据骑行准入、单行、道路类别和路面权重选择路线。已排除高速、机动车专用路、明确禁止/私有访问和无法处理的条件访问；步行道路仅在明确允许骑行时纳入。

起终点匹配到道路节点，最大匹配距离为 180 m。所选坐标与最终可骑行道路节点可能不同，结果终点以匹配节点为准。没有可连接路线时返回失败，不画直线假装道路。最多输出 4,096 个路线节点，UI 只取有界窗口或总览抽样。

当前实现仍没有完整地址/POI 搜索、交通限制关系与复杂转向限制、基于车道的指令、实时封路或交通信息，也没有完成真实 GNSS 的道路匹配与偏航触发。PC 后端已接入同一 A* 的 REROUTE 请求路径，但实际偏航判定、到达半径和现场可靠性仍需真机实现与道路验证。新规划路线目前保存在本次进程中，跨重启的个人路线归档需接入独立存储后端。

因此本轮交付的是可运行的二维离线地图与选点道路规划核心；完整商用导航还需要上述数据和定位工作。

## 实测方法与结果

核心测试在真实文件上校验冷加载、缓存命中、九级缩放、损坏数据、两个不同目的地、取消、覆盖范围与坐标系。

最终 CTest 为 40/40 通过，15 组 FULL/PARTIAL 画面逐像素一致。核心冷加载样本为 5 ms、读取 547,217 B，同视野缓存样本为 0 ms、0 B（计时分辨率内）；4,090 m 核心 A* 样本为 94 ms，1,729 m UI 后台选点规划样本为 12.73–12.89 ms。100 次刷新样本中位数为 4 ms，P95 为 5–6 ms，最大值为 6–8 ms。这些是当前电脑与测试条件下的结果，不能替代真实显示端口和 TF 卡测量。

PC LVGL 测试执行长按选点、后台规划、预览、开始、返回菜单、结束、准星、放大/缩小，并在 480×854 RGB565 下比较 FULL 与 40 行 PARTIAL 刷新。画面与性能原始结果见 `docs/previews/xian-color-map/validation.json`。8 个受保护的开机、首页、个人页源文件 SHA-256 一致。

性能采样把底图平移 2 px 并调用 `lv_refr_now`，连续取 100 帧，记录中位数、P95 和最大值。它测量 LVGL 软件绘制和内存刷新，**不包含真实屏幕扫描、TF 卡物理传输、GNSS 或 SDL 的完整呈现延迟**。缓存命中读字节为 0；示例约 4.1 km 的 A* 与约 1.7 km 的 UI 选点路线分别记录核心耗时和后台端口耗时。后者带 64 KiB 文件缓存，二者不应直接作为算法加速比比较。

电脑成绩不能外推为 STM32 的 60 FPS。真机应分别测冷读取、解压、绘制、刷新与最差帧耗时。

## TF 卡与板端接口

建议把同一版本资源目录整体部署到 TF 卡 `/maps/xian/`，包含 `.btiles`、`.bgraph`、兼容 `.bmap/.broute`、manifest 和许可说明。先写新目录、完成 CRC 检查，再切换目录；停止导航/关闭文件后更新并重新打开，不能运行中逐个覆盖文件。

共享核心文件：

- `ui_offline_tiles.h/.c`：`ui_offline_tiles_open`、`ui_offline_tiles_window`、瓦片与地名缓存。
- `ui_offline_graph.h/.c`：`ui_offline_graph_open`、`ui_offline_graph_workspace_size`、`ui_offline_graph_plan`。
- `ui_nav_raster.h/.c`：调用者提供的双缓冲生命周期。
- `ui_nav_map_provider.h/.c`：请求 ID/路线版本校验与快照提交。
- `ui_nav_session.h/.c`：PLAN / START / STOP / REROUTE 与会话状态。

板端需要实现 `ui_offline_map_io_t.read_at(context, offset, bytes, count)` 与文件大小，用 FatFs/TF 读取任务封装。核心没有 stdio、Windows、LVGL 或 malloc 依赖。后台取队列、读取/计算、发布结果，UI 只消费快照。初始化时的完整索引/图 CRC 检查也应放在工作任务。

`ui_nav_raster` 的新帧采用必须在 LVGL 绘制安全时段进行；DMA/缓存一致性、32 字节对齐与缓冲归属需结合实际显示端口落实。本项目已有 LVGL 9.3 DMA2D 后端只接受无缩放、无旋转的图像条件，不能把地图旋转性能全部归功于 DMA2D；软件变换仍需实测。

### 内存建议

| 项目 | PC/共享核心占用 | 板端建议 |
| --- | --- | --- |
| 24 张 256×256 RGB565 缓存 | 3 MiB | STM32 可先使用 16 槽，2 MiB，再按命中率调整 |
| 两块 768×768 RGB565 缓冲 | 2.25 MiB | 外部 SDRAM，独立于 LVGL 对象堆 |
| 480×854 双显示帧 | 1.56 MiB | 外部 SDRAM/LTDC 对齐与 D-Cache 管理 |
| 图 A* 工作区 | 3,044,136 B，约 2.90 MiB | 可由 ESP32-S3 PSRAM 承担计算，UI 继续在 STM32 |
| 全路线固定结构 | PC `sizeof` 327,744 B | 4,096 点；控制副本数量 |
| 地图快照 | PC `sizeof` 28,520 B | mailbox、UI 副本另行计入预算 |
| 瓦片缓存元数据 | PC `sizeof` 31,120 B | 包括最多 32 槽的有界地名缓存 |

ESP32-S3 的 PSRAM 不与 STM32 地址空间共享，不能直接把 ESP32 上的像素指针交给 STM32/LTDC。建议 STM32 的 SDRAM 放显示、瓦片和 UI；ESP32 负责通信/可选寻路，通过现有通信接口传输路线结果。先按约 4 MiB 的寻路工作区与路线预算预留 PSRAM，再测通信并发时的实际可用内存。

TF 读取建议使用多扇区缓冲与异步队列；地图读取优先于后台更新，GNSS 与 UI 线程不等待 TF。真正的续航和帧率还取决于面板刷新、SDMMC 接线/时钟、SDRAM 带宽、后台通信和整机功耗，本轮未测这些物理指标。
