# 最后一轮 UI 审查与优化

日期：2026-10-02。工程：`Lvgl_Project`。屏幕：480×854，3 英寸触摸屏；输入：5 个实体键和带按压的旋转编码器。

本轮已审查页面布局、文本边界、触摸与编码器输入、动效策略、路由、缺失与失败反馈。修改已安装到用户工程并完成 PC 构建与回归。保留纯黑背景、中性灰卡片、黄色主色，以及已确定的 PRTS 启动和弹性胶囊风格。

## 判断与范围

**事实：**原工程还有统计口径错误、首页详情入口复用历史焦点、只读信息行显示操作焦点、快速旋转丢失滚动步进等问题。这些会影响用户判断，比继续增加装饰动画更值得优先处理。

**判断：**这轮应收束视觉规范并补齐交互反馈，保留已经确认的视觉基准。过多颜色、边框和重复说明会压过关键数值；骑行页的速度及心率/功率区间色仍有明确用途，予以保留。

**边界：**软件渲染通过不等于商用发行验收，PC FPS 不代表 STM32 真机 FPS。本轮没有修改硬件驱动、重新制作开机动画，或生成虚假的蓝牙连接和收藏路线。

## 本轮发现和修复

| 区域 | 原问题 | 本轮处理 |
| --- | --- | --- |
| 个人统计 | 数字长度变化后字号、单位位置不一致 | 按实际宽度选择数字字号；四项数值与单位共用基线，限制超长文本范围 |
| 个人身份 | 身份卡点击重新进入自己；焦点编号残留 | 身份区改为信息展示；焦点从刷新按钮开始，按视觉顺序遍历 |
| 30 天活动 | 摘要使用终身累计；未区分日期缺失 | 使用后端 UTC 筛选近 30 天记录，排除未来和过期记录；日期未知、记录无日期、仅有累计值时显示相应缺失状态 |
| 记录读取 | 一次在栈上复制 100 条含轨迹的记录 | 改为逐条读取；活动与详情暂存使用可映射到 `UI_LARGE_RAM` 的缓冲 |
| 首页最近骑行 | 依赖历史列表当前选中记录 | 单独读取最新记录；不再误入旧记录；无法读取详情时给出反馈 |
| 首页触摸 | 按下直接切换缩放状态 | 使用共用按压/释放动画，围绕按钮中心缩放，拖动丢失按压时恢复 |
| 滚动列表 | 样式不一致；部分列表缺少统一滚动提示 | 设置、历史、成就、报告、指标选择统一黄色滚动条和减少动效策略 |
| 报告滚动 | 快速旋转以当前画面位置重复计算，丢失部分步进 | 改为在动画终点上累加，连续正反转仍保留每次输入，边界处限制目标 |
| 设置/系统信息 | 长设备名挤在窄值槽；只读行显示黄色操作焦点 | 只读值独占完整第二行；隐藏重复英文说明；只读行不显示操作边框，也不发送命令 |
| 数据布局 | 列表、预览与主操作层级不清 | 保留结构预览和滚动条；更换指标说明简化；保存使用黄色主按钮 |
| 区间编辑 | 蓝灰按钮；值与单位拥挤；编辑能越过相邻边界 | 统一黑黄灰；值右对齐；增减限制在相邻阈值之间；触摸选行与编码器编辑一致 |
| 区间编辑退出 | 部分全局按键被弹窗吞掉 | 电源、骑行和控制中心入口先结束草稿编辑，再交由全局逻辑处理 |
| 设备连接页 | 搜索反馈写入此页不可见的底部容器 | 在本页显示蓝牙关闭或服务尚未接入的原因；保留外设状态更新接口 |
| 收藏路线 | 占位文案暗示数据接口已就绪 | 独立空态与返回操作，删除假就绪声明；继续使用中性路线图标 |
| 报告/导航 | 卡片边框偏亮，导航指令栏有旧色值 | 报告用中性灰边框和分隔线；导航指令栏统一主题；距离单位跟随数值并对齐 |
| 减少动态效果 | 页面切换、脉冲、延迟入场、卡片滚动及导航提示执行策略不一致 | 统一策略；减少动效时跳过页面移动和导航脉冲，取消入场等待，滚动直接到目标 |
| 数值动效 | 超大合法距离可能溢出 32 位计数动画目标 | 超出范围直接显示；长文本按字号或省略策略限定，不覆盖相邻数值 |
| 报告总结 | 将区间占比推断成节奏稳定；结尾文案过长且未区分保存状态 | 改为实际距离、爬升和 Z3 有效时间占比；明确已保存/尚未保存，不给无依据的训练结论 |
| 保存重试反馈 | 重试成功后，已打开的报告保留旧的未保存状态 | 持久化成功确认后就地更新保存提示，保留内容和滚动位置；覆盖失败→重试成功场景 |

删除了只为旧测试保留的屏幕外兼容文本。测试现在检查实际可见内容及交互结果。

## 验证结果

- 完整 CMake/Ninja 构建成功；CTest **32/32** 通过。
- 整屏刷新与部分缓冲刷新 **225 组 480×854 帧逐像素一致**，包括启动、胶囊展开、转场、各主要页面和缺失状态。
- 渲染检查没有发现缺字、图层分配失败或 LVGL 内存错误。主要页面及报告底部已做画面核对。
- 新增回归包含快速连续正反转、区间边界与取消、触摸选行保存、最近记录入口、设备失败反馈、活动日期筛选、只读信息无命令、减少动效与超大距离。
- 集成测试中的 `error=-1001` 来自主动注入的关机失败场景；断言检查失败后没有假关机，不是未处理的现场故障。

截图使用测试数据展示状态和布局，不能当作真实骑行或外设已连接的证据。快照测试主动隐藏性能文字以便稳定比较；运行模拟器仍默认显示 FPS、CPU 估计、渲染与刷屏耗时。

## 保留的数据接入接口和限制

1. 实时数值继续使用 `ui_stm32_services_submit_ride_data()` / `submit_ride_patch()`，按字段质量显示有效、缺失和过期状态。原有状态、导航、天气及诊断提交接口保留，详见[硬件数据与任务接口](硬件数据与任务接口_v1.4.0-rc1.md)。
2. 活动日期从历史存储的 `now_utc` 回调读取。新增 `ui_ride_history_repository_now_utc()`，由 UI 线程调用；回调应快速读取已缓存的 RTC/GNSS UTC，不应阻塞读卡或等待蓝牙。独立使用个人页可调用 `ui_profile_page_set_activity_time()` 后刷新。
3. 活动矩阵当前是以刷新时刻为基准的 30 个滚动 24 小时区间，统计已载入的最多 100 条记录。它尚不是按当地自然日计算的完整归档统计；若 30 天内超过 100 次骑行，需要后台提供全量按日聚合，不能把当前窗口当作完整总数。
4. 外设页提供 `ui_devices_page_set_status(kind, status, color)` 和 `ui_devices_page_set_feedback(message)`。这些是 **UI 线程接口**；蓝牙任务应先投递状态再由 UI 线程更新，不能从 ISR 直接操作 LVGL。扫描、发现列表、配对、断连恢复和协议仍须接入真实服务。
5. 收藏页当前只有独立入口和空态；尚未实现路线目录、GPX/FIT 导入、收藏存储和真实导航引擎。报告轨迹预览继续使用记录提供的有效采样点。
6. `UI_LARGE_RAM` 在 PC 上为空；板级工程仍须正确配置对应链接段、初始化外部 RAM，并测量 UI 任务栈和 LVGL 堆水位。

## 软件收束后的下一步

建议冻结当前视觉基准，先接真实数据验证缺失、断连、超长数值、存储失败和输入冲突，再按测量结果调整性能。真机应测展开/收起的帧时间及触摸到显示的延迟、显示 DMA 与存储/BLE 并发、内存水位和长时间稳定性。3 英寸屏幕的日光可读性、戴手套/湿手触摸也需要实物评估。

这些结果出来前，不应承诺稳定 60 FPS 或认定达到商用发行标准。减少动态效果会降低装饰动画，但保留清晰的状态变化和操作结果。
