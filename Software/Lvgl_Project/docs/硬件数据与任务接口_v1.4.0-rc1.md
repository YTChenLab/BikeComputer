# 硬件数据与任务接口

日期：2026-10-01。适用版本：v1.4.0-rc1。目标工程为本目录的 `src/`，不依赖另一份旧软件目录。这里定义真实数据接入和任务职责，没有实现 GPIO、I²C、SPI、LTDC、FMC、BLE 协议或电源驱动。

2026-10-02 补充：个人页的活动时间通过历史存储 `now_utc` 回调提供，`ui_ride_history_repository_now_utc()` 在 UI 线程读取快速缓存；独立页面可用 `ui_profile_page_set_activity_time()` 后刷新。外设页提供 `ui_devices_page_set_status()` / `ui_devices_page_set_feedback()`，必须由 UI 线程调用。日期统计窗口、设备配对和收藏路线的实际完成边界见[最后一轮 UI 审查与优化](最后一轮UI审查与优化_20261002.md)。

## 一、初始化和线程所有权

1. 板级工程先初始化内存、LVGL 显示端口、RTOS 队列、互斥锁和存储设备。存储回调需具备可读的启动状态。
2. 在唯一 UI 线程调用 `ui_stm32_services_register()`，注册命令入队、历史分页任务通知及 `lock/unlock`。再注册历史存储和 `ui_preferences_register()`。需要背景和声音时，提前注册各自端口。
3. 调用 `ui_app_init()`。它会读取历史/checkpoint/配置；允许启动时进行阻塞 I/O，不应在活跃动画中重复调用。
4. 初始化结束再启动传感器、输入和业务生产任务。所有 LVGL API、页面更新和 UI 观察者只在 UI 线程执行。UI 任务持续调用 `lv_timer_handler()`；`lv_tick_get()` 必须使用可靠的单调时钟。

`lock/unlock` 用 RTOS 互斥锁或适当的短临界区实现。端口初始化在生产者启动前完成。任务可以调用 `submit`/`complete`；ISR 只投递底层通知，随后由任务提交。不要在持有 UI 互斥锁时等待存储、蓝牙或 LVGL。

可编译示例：[ui_board_adapter_example.h](examples/ui_board_adapter_example.h)、[ui_board_adapter_example.c](examples/ui_board_adapter_example.c)。它接收你的真实服务端口；未提供必需的存储与后台任务回调时返回失败。示例作为 CMake 对象目标进行编译检查，不链接到 PC 主程序，不会伪造硬件数值或命令成功。

## 二、骑行数值契约

头文件：`src/ui/models/ui_ride_data_model.h`。完整快照入口为 `ui_stm32_services_submit_ride_data()`；字段合并入口为 `ui_stm32_services_submit_ride_patch()`。提交会复制数据，调用结束后可复用原缓冲。

| 字段枚举 | 结构成员 | 统一单位/含义 |
| --- | --- | --- |
| SPEED | speed | km/h，0 合法，负数及非有限值无效 |
| HEART_RATE | heart_rate | bpm，0 无效；断连应清除有效位 |
| POWER | power | W，显式有效的 0 合法 |
| CADENCE | cadence | rpm，显式有效的 0 合法 |
| GRADE | grade | %，上坡正、下坡负 |
| DISTANCE | distance | km，会话活动距离计数；暂停期间应冻结 |
| AVERAGE_SPEED / MAXIMUM_SPEED | average_speed / maximum_speed | km/h，用于实时字段；报告均速由活动距离/活动时长计算 |
| ALTITUDE | altitude_m | m，允许负海拔 |
| ASCENT | ascent_m | m，后端滤波后的累计爬升计数 |
| CALORIES | calories_kcal | kcal，后端计算的累计热量计数 |
| TEMPERATURE | temperature_c | ℃，目前是 int8_t 整数精度，0 ℃ 合法 |
| TIME | clock_hour / clock_minute | 本地显示时间；活动计时另用 timer_ms |
| GNSS | satellites | 当前卫星数；开关、导航质量另走状态/导航接口 |
| BATTERY | battery | 0–100%；充电状态走状态适配器 |
| LAP | current_lap / total_laps | 后端提供的计圈信息；此接口不包含新增圈标记命令 |
| POSITION | latitude / longitude | 十进制度，纬度 ±90、经度 ±180；0,0 在显式有效时可合法 |

对每个字段调用：

```c
ui_ride_data_set_quality(&sample, UI_RIDE_FIELD_SPEED,
    true, wheel_sample_valid, wheel_sampled_at_ms, 2000U, UI_DATA_SOURCE_WHEEL);
```

`supported=false` 表示不具备能力；`supported=true, valid=false` 表示具备能力但本次无有效数据。字段只在能力和有效位同时存在、数值合法且未过期时显示。`stale_after_ms=0` 表示不随时间过期，适用于持续受控的配置/累计计数，不应随意用于实时速度或心率。2000 ms 是示例门限，最终按实际传感器周期配置。

来源可用 GNSS、WHEEL、BLE、BAROMETER、BOARD、FUSED；DEMO 只用于 PC。真实接入必须设置 `quality_known=true`。旧接口的隐式数值推断仅保留兼容用途。

### 时间和会话

- `sample_time_ms` 为快照形成时间；各字段 `quality[field].sampled_at_ms` 为实际采样时间。它们必须与 UI tick 使用同一单调时间基准，不能把 Unix 秒或另一任务的局部计数放进去。
- 32 位毫秒时钟支持环绕比较。有效年龄需处于半个 32 位范围以内；不应提交来自未来时钟域的数据。
- `timer_ms` 为 64 位活动记录时长，UI 卡顿、关屏或切页不能使它停止；暂停时冻结，恢复后继续。不得把开机 uptime 当成活动时长。
- `timestamp_utc` 为有效 UTC 秒；RTC 未就绪时填 0。显示本地时间与存档 UTC 是不同职责；板级需统一时区策略。
- START 命令的 `value` 携带会话标识，按 `uint32_t` 解释。后端重置记录计数、建立对应 `session_id`，先提交新会话完整基线，再确认 START。暂停、恢复、结束必须处理最终快照和活动计时，再确认命令。
- 新会话用完整快照建立。patch 拒绝不同会话和旧时间数据；多个独立传感器任务应先汇聚到一个融合/记录任务，由它统一维护 `sample_time_ms/timer_ms/session_id`，随后发完整快照或 patch。不要让各传感器各自覆盖公共计时头。

统计在生产数据提交路径中更新，UI drain 只刷新显示。相同/倒退活动时间不累计；心率断连样本排除，功率 0 纳入。当前均值按“本次有效采样值 × 与上一活动时间的差值”加权，是离散区间近似，不能当作精确连续积分。数据丢失的大间隔无法由 UI 恢复。

报告保留最多 120 个带活动时间、质量位和 GPS 坐标的预览点。完整原始样本和完整路线必须由记录任务另行保存，此预览不是 FIT/GPX 原始日志。海拔平滑、轮速/GNSS 源切换、异常尖峰过滤和热量算法属于融合/记录后端；UI 不会凭空产生这些值。

## 三、状态、导航、天气和诊断

| 数据 | 接口 | 关键约束 |
| --- | --- | --- |
| 时钟、电量、GNSS、连接、控制、媒体 | ui_stm32_services_submit_state | 按 UI_STATE_ADAPTER_* 组提交。同组包含多个成员，必须提交整组最新快照，避免清空未更新的同组状态 |
| 转向和局部路线 | ui_stm32_services_submit_navigation | demo=false；位置有效性、采样/过期时间；路线窗口最多 16 点；提供有效地理原点和 meters_per_pixel |
| 天气 | ui_stm32_services_submit_weather | quality_known=true；valid 及采样/过期时间；获取失败不能显示 PC 演示值 |
| 设备型号、固件、剩余空间、健康 | ui_device_info_submit | 字符串由邮箱复制，UI 线程更新系统信息；storage_free_bytes 为字节，非 MiB |

状态组 STATUS 中设置 `status_quality_known=true`，并分别提供 `clock_valid/battery_valid`。RTC 未定位、电量计故障时可分别显示 `--:--`、`--%`；旧调用未设置该标志时保留旧的“提交即有效”行为。

导航只绘制实际局部路线/位置，用户缩放不会被新遥测覆盖，航向按最短角过渡；过期位置进入 GPS_WEAK。没有道路底图或规划引擎时，不会因为输入经纬度而自动获得街道和路线。无 GPS 的骑行报告明确提示无有效轨迹。

## 四、异步命令

`services.dispatch_command(command, context)` 在 UI 线程执行，只允许复制命令到后台队列并立即返回。不能在这里等待 GNSS、蓝牙、文件 I/O 或播放声音。无法接受时返回 false。后台完成后调用 `ui_stm32_services_complete_command()`，保留原始 `id`。

| 命令族 | value / 后端职责 |
| --- | --- |
| WIFI / BLUETOOTH / GNSS / POWER_SAVE / TOUCH_LOCK | 0/1；实际执行成功后返回相应真实状态 |
| SOUND / BRIGHTNESS | 0–100；亮度配置持久化范围目前为 1–100，关屏单独处理 |
| RIDE_START | 新会话标识；重置记录状态并发布完整基线 |
| RIDE_PAUSE / RESUME / FINISH | 冻结/恢复/结束活动计时和计数，提交边界快照 |
| RIDE_SAVE | 运行已冻结的存储事务，见下一节 |
| DISPLAY_SET_ENABLED | 0/1；仅屏幕/背光，不停止传感器和记录 |
| SYSTEM_SHUTDOWN / RESTART | UI 已先结束并保存当前骑行；板级安排安全电源动作，不能重新丢弃记录 |
| MEDIA_* / RIDE_UPLOAD | 真实媒体/上传服务；未实现时返回 REJECTED/FAILED，不能假回 SUCCESS |

成功、失败、超时、拒绝都保留。匹配的成功 ACK 可以携带状态快照，在通知 UI 结果前应用；重复/迟到 ACK 不覆盖更新后的状态。结果队列满时保留结果并重试 ACK，不要重新执行硬件操作。默认命令超时 1500 ms，当前 SAVE 为 5000 ms；超时不等于后台任务已取消。

关机/重启前如果开始命令尚未确认，先等开始结果，再结束/保存。保存失败保留待保存状态和电源意图；重试成功后继续电源动作。硬件不可逆断电的最后执行时点由板级管理，必须确保实际持久化完成。

## 五、历史存储和恢复

注册 `ui_ride_history_storage_t`：启动 `load`、`now_utc`、`store`；建议同时实现幂等 `append_record`、`load_checkpoint/store_checkpoint` 和 `load_page`。`load` 返回最近最多 100 条，按旧到新排列；`load_page` 返回指定 newest_offset 开始的记录，按新到旧排列。

`now_utc` 必须读取已缓存的 RTC 时间，不能在 UI 上进行慢总线读取。真实存储回调返回 OK 的前提是完成可恢复的提交；FatFs 的数据/目录刷新、断电行为和底层设备保证由适配器负责。

```text
UI：stage(summary) → RAM 待保存 → begin_commit() 冻结事务
存储任务：commit_worker() → intent checkpoint → 幂等追加 → final checkpoint
UI：process() → 发布历史/累计/待保存状态 → 原命令 ACK 驱动界面
```

STM32 SAVE 分发包装器已调用 `begin_commit()`。后台只调用 `commit_worker()`，完成后 ACK 同一命令 id。`commit_pending()` 是同步启动/测试便捷接口，会发布 UI 模型，禁止在存储工作任务或活跃动画回调中使用。

旧历史分页使用 `services.request_history_page_worker` 通知存储任务，后台运行 `page_worker()`。UI 的 `request_page()` 先查缓存，否则返回 PENDING；界面保持原内容并暂停选择，待 UI 发布结果后替换。页面读取和保存共用一个串行事务槽。队列失败/损坏/未配置有失败反馈，不回退到 UI 线程读文件。旧 `load_page()` 便捷接口仍是阻塞接口，供启动或测试调用。

保存超时而后台稍后真实提交成功时，UI 通过提交代数对账；不会重复添加累计统计。保存 intent 已写入后，支持恢复待保存/追加已完成但元数据未完成的事务。**活动骑行的原始数据掉电恢复，以及 intent 首次持久化前的突然断电，不在此汇总事务的保障范围内。** 这些需要记录后端持续日志。

PC 文件格式当前为 v3，兼容读取 v1/v2。v3 包含 120 点真实时间轴/质量/GPS；字节 76 高四位记录距离、速度、海拔、爬升可用性；字节 77 的 bit0 是估算时间轴，bit1 是热量可用性，bit2 是聚合可用性已知。旧记录没有 bit2，保留其已有聚合数值，不重新推断为真实有效。实现有 CRC、临时文件、备份恢复和幂等追加；不要直接 fwrite 结构体。

首页最近摘要增加 `ui_home_data_t.last_ride_available / last_distance_available / last_ascent_available`，由应用根据可读的最近保存记录及其聚合质量位推导；无记录或对应字段不可用时显示 `--`，合法零值仍显示零。正常后端只需正确保存历史及质量位，应用会自动刷新首页、个人习惯与成就。若有直接更新首页模型的旧调用方，需明确填充这三个标志。它们不改变历史／配置文件格式，也不引入新硬件驱动。个人页的平均每次用时使用终身累计活动秒数除以已保存次数，暂时没有可读详情缓存时保留累计统计并明确提示。

## 六、配置存储

`ui_preferences_register()` 提供启动 `load`、后台 `store`、非阻塞 `request_worker`；配置固定 128 字节，BKPF v2、规范字节序和 CRC，兼容读取 v1。后台收到通知后调用 `ui_preferences_worker()`。读取/修改流程为 `get()` → 修改需要的成员 → `submit()`；不要用零初始化结构覆盖所有默认配置。

支持姓名/签名、亮度、音量、自动暂停、减少动态效果、自动息屏时间及四个心率/功率区间边界。心率边界 1–250 bpm、功率 1–3000 W，必须严格递增。配置 worker 保存快照；保存期间到达的新改动保持 dirty。失败保留改动并按 5 s 门限重试。设置页显示默认配置、待保存、已保存、保存失败或未接入。

新增 `dashboard_fields[6]` 和 `dashboard_preset`，分别为六格字段 ID 和方案编号（巡航 0、训练 1、爬坡 2、自定义 3）。字段 ID 复用 `ui_ride_field_t`，只能选择 `ui_dashboard_field_definition()` 支持的 12 项，不允许重复；预设编号必须与预设字段匹配。调用 `ui_dashboard_preset_fields()` 可填充预设。blob 的 116–121 字节保存字段，122 保存方案，123 保留为零，124–127 仍为 CRC32。v1 读取时保留已有参数并采用巡航布局，下次保存写为 v2。旧调用方全部省略新字段时保留当前布局；新调用方仍应通过 `get()` 修改快照。

布局只影响显示。生产任务继续通过骑行数据模型提交，按字段设置能力、有效性、TTL 和来源；主骑行页和两页扩展数据会显示真实值或 `--`，不需要任务直接调用 LVGL。心率/功率换到其他格时，区间条使用同一当前会话阈值。

区间修改在下一次骑行生效，避免本次报告被后改阈值污染。默认边界是预设值，未实现根据个人 FTP/LTHR 自动计算。姓名目前通过配置接口更新，没有新增屏幕全键盘。显示固定公制，尚无英制单位切换。

## 七、五键、编码器与触摸

单个输入任务每 5–10 ms 提交一次 `ui_stm32_services_sample_inputs(pressed_mask, encoder_delta, now_ms)`。pressed_mask 中 1 表示按下，先归一化 GPIO 电平；encoder_delta 是已解码的逻辑旋转步数。去抖 25 ms，长按 1200 ms，长按后不再发短按；短按在松开确认后产生。

| 实体输入 | 标识 | STM32 默认短按 / 长按 |
| --- | --- | --- |
| PWR | UI_HW_KEY_POWER | 关屏/唤醒 / 电源菜单 |
| BACK | UI_HW_KEY_BACK | 返回 / 结束骑行确认 |
| PGUP | UI_HW_KEY_PREVIOUS | 上一页 / 无 |
| PGDN | UI_HW_KEY_NEXT | 下一页 / 无 |
| MENU | UI_HW_KEY_MENU | 快捷控制 / 骑行开始、暂停、恢复的上下文操作 |
| ENC_SW | UI_HW_KEY_ENCODER | 当前焦点确认 / 快捷控制 |

`UI_HW_KEY_MENU` 与旧枚举 RIDE 同值，保留兼容。不同外壳布局用 `ui_stm32_services_set_key_map()` 在输入任务启动前重映射，传 UI_INPUT_COUNT 禁用对应事件。PC 鼠标右键支持双击；基础硬件去抖器没有额外实现双击计时。

触摸通过 `ui_input_message_t` 的 TOUCH_BEGIN/MOVE/END/CANCEL 和像素 x/y 送入 UI 输入队列。不要把失去触点当成点击松开。标准 LVGL 控件还需要板级 indev `read_cb`；它必须在 UI 线程从同一份触摸样本读坐标，并协调应用手势路由，先处理取消/拦截，再让 LVGL 处理释放，避免双重派发点击。触摸锁定保留实体键操作；息屏唤醒会消费第一次输入。

## 八、资源、内存和验收

- 当前黑黄主题默认 `UI_BACKGROUND_BITMAP_ENABLED=0`，不加载全屏背景位图，页面根始终不透明黑色。可选资源 API 保留；编译时显式启用位图主题后，`UI_BACKGROUND_PLATFORM_STM32` 禁用 PC 文件路径，背景端口可返回持久存在的 RGB565 descriptor。对象生命周期结束后再释放底层图像。
- `ui_sound_set_backend()` 的回调在 UI 线程运行，必须将音效通知到音频任务；不能同步等待 I²S/蜂鸣器完成。
- 历史缓存/事务工作区可通过 `UI_LARGE_RAM` 放入外部 RAM，链接脚本和区域初始化由板级实现。当前两个 100 条记录工作区及 10 条分页缓存是主要静态大块；不能默认把全部放到 MCU 内部 RAM。
- RGB565 单帧 480×854×2 = 819,840 字节；双帧 1,639,680 字节。缓存一致性、DMA 可访问性、字节序和 flush_ready 时机仍需板级验证。
- 动态文本进行 UTF-8 清理和字形回退，未知字显示 `?`；不是完整 CJK 字库。量产所需字集加入 `tools/ui_extra_characters.txt` 再生成，不要在 UI 线程临时加载字体。
- 电脑回归验证接口逻辑；上板后至少验证真实 0、断连/过期、暂停时计时冻结、取消不提交、保存失败/重试、关机等待保存、ACK 迟到、存储耗尽、部分刷新、长时间运行。实际刷新和输入延迟需实测。
