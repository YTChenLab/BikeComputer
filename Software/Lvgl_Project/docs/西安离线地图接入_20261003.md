# 西安真实离线地图接入（2026-10-03）

> 本文记录第一次矢量包接入。后续彩色瓦片、选点 A*、4,096 路线节点与性能结果见 [彩色离线地图与选点导航](彩色离线地图与选点导航_20261003.md)。下方容量与测试数量是该历史阶段的结果。

当前 PC 模拟器默认读取真实 OSM 矢量文件。地图卡片 464×540、交互坞 464×226、黄色液体胶囊保持上一轮标准。旧合成地图端口只用于原有回归测试，不再作为主程序的默认地图。

## 数据与覆盖

- 原始数据来自公开 Overpass 实例；Geofabrik 主站和备用站在本机连接超时，故本轮没有取得陕西省 PBF。
- 最终原始 JSON 为 67,809,764 字节；数据快照 **2026-07-24T11:04:51Z**，下载于 2026-10-03。查询、来源、时间和 SHA-256 均保留在 `assets/maps/xian/manifest.json`。
- WGS84 城区矩形：东经 108.78～109.15、北纬 34.12～34.46。**不是西安市完整行政区域。**
- 城区道路、水系、公园；建筑细节限制在东经 108.92～108.98、北纬 34.25～34.28。空白地块不会补画假建筑。
- 地图包 `xian-urban.bmap`：24,801,004 字节（约 23.65 MiB）、1,258 个索引网格。道路 95,973 段、建筑 103,637 个绘制面、公园 46,436 个绘制面、水体 4,046 个绘制面。这里的面数包含三角剖分，不能解释成建筑或公园数量。
- 保留真实简单多边形、可拼接且无内环的多多边形；带内环对象和不能可靠剖分的形状省略，避免错误填满孔洞。没有道路车道数、交通灯状态或实时路况时，UI 不推断这些细节。
- 数据依据 ODbL 1.0 使用；地图内有署名，资源目录有 LICENSE 和可重建的查询、格式、转换源码。

## 路线与回放

提供约 **3,948 m、99 个节点**的“西安城区骑行”路线，起点 (108.934547, 34.25794)，终点 (108.964295, 34.2699991)。转换工具在电脑上沿 OSM 连通道路做 Dijkstra，检查 bicycle/access/oneway/motorroad 标签；这条路线供真实地图显示验证，实际道路通行条件仍需实地验证。

- `.gpx` 为规划路线，没有伪造骑行时间戳、海拔或历史记录。
- `.broute` 为供共享 C 接口读取的路线文件，带累计距离、道路名和 CRC32。
- PC 默认沿路线以 18 km/h 的模型回放位置；`UI_NAV_SOURCE_REPLAY` 与设备/手机来源独立。地图帧的 `demo=false`，引导模型的 `demo=true` 表示模拟位置。
- 转向由相邻道路几何角度派生，下一路口有真实坐标，相机沿现有逻辑自动放大。它是基础几何转向，尚不是带交叉路口拓扑、车道或环岛出口语义的完整商用引导引擎。
- 没有 DEM 时爬升无效，显示未知；预计用时按回放速度计算，不代表实测骑行成绩。
- 偏航重规划、手机传输、在线更新、任意目的地规划、路线删除的后端能力没有注册，保留现有禁用/不可用反馈；不会伪造成功。

## 共享 C 接口与 STM32 移植

`src/services/ui_offline_map.h/.c` 不调用 LVGL、不依赖 stdio、Windows 或动态内存。板端提供 `ui_offline_map_io_t.read_at(context, offset, bytes, count)` 和文件大小，可直接封装 FatFs 或外部存储读取。解析显式小端字段，校验头 CRC、范围、记录长度、瓦片 CRC，拒绝不支持的版本和 GCJ-02 坐标。

板端存储任务处理 `ui_nav_map_backend_t.request` 的队列：

1. 初始化文件句柄并调用 `ui_offline_map_open`。
2. 复制当前地图请求到有界队列；UI 线程立即返回，不进行磁盘 I/O。
3. 存储任务调用 `ui_offline_map_read`，需要路线时调用 `ui_offline_route_window`。
4. 用 `ui_nav_map_provider_submit` 提交快照。旧请求 ID、旧路线修订会被 mailbox 拒绝。
5. 文件缺失、损坏、超出覆盖和坐标系不一致分别返回对应结果；无有效 GNSS 时不要提交模拟位置为 DEVICE 来源。

`src/services/ui_offline_route.h/.c` 是同样的文件读取接口，当前最多 512 个路线节点。实际 GNSS 生产者应做时间戳、定位质量、投影到路线、航向滤波、转向步骤推进和偏航判定，再提交 `nav_model_t` 与 `ui_nav_session_t`。PC 的回放函数不能替代这些板端逻辑。

## 资源与性能预算

| 项目 | 当前实测/边界 | 板端含义 |
| --- | --- | --- |
| 外部地图文件 | 23.65 MiB | 不能放入 ESP32-S3-N16R8 的 16 MB Flash，需 TF 卡/足够容量的外部存储；PSRAM 不能替代持久存储 |
| 地图输出帧 | PC `sizeof` 25,392 B | 当前/待处理 mailbox、绘制副本和 UI 静态工作帧合计约 100 KiB；建议地图任务数据单独规划内存区域 |
| 全路线固定缓冲 | PC `sizeof` 41,024 B | 最多 512 点，当前只用 99 点；移植时可按实际需要缩小上限 |
| 窗口绘制容量 | 道路 192、面 192、地名 12、路线 128 点 | 有界选择，建筑/公园/水体分别保留容量；不是把全部城市对象塞进 LVGL |
| 中文 UI 20/24 字体 | PC 两个对象合计 620,384 B | 共 1,446 个运行时字符；ARM 最终占用需看链接 map，不能按生成 C 文件大小估算 |
| 抽样地图窗口 | 6 网格、3,787,356 B 原始记录、PC 内存读取约 38 ms | 只代表该电脑核心解析测试，不是 STM32 或 TF 卡成绩。10 MB/s 持续读取下仅数据传输就约 0.38 s |
| 绘制缓存 | 480×854 RGB565 一帧 819,840 B | 双帧约 1.56 MiB，另外预留 LVGL 堆、栈及地图任务工作区 |

地图后台更新与 UI 动画帧率分开：当前静止视野不重复请求，移动达到阈值或视野/路线变化才加载。已有绘制数据可以继续显示，加载时不阻塞液体胶囊。地图较密时会按道路等级、距离、图层配额取舍，尚未实测 STM32 上 60 FPS；下一阶段应测 SD 吞吐、解析耗时和渲染耗时，再决定细分瓦片、预制 LOD、路线走廊缓存或是否把读取/计算交给 ESP32。

容量依据：[ESP32-S3-WROOM-1 官方规格书](https://documentation.espressif.com/esp32-s3-wroom-1_wroom-1u_datasheet_en.pdf)，N16R8 为 16 MB Flash / 8 MB PSRAM。
