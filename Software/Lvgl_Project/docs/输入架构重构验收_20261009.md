## 3. 不重复处理的依据

`ui_input_map_physical_event()` 没有状态变量、clock 调用、计时窗口或编码器跳变解码。CLICK、DOUBLE_CLICK、LONG_START 分别映射一次；DOWN/UP/LONG_REPEAT/LONG_END 无动作。编码器档位逐档执行，不存在旧 encoder_pending 或四相累计阈值。

语义测试对 0、UINT32_MAX、25、1200、280、1 等时间戳得到相同行为；正负 1..64 档全部校验，超限和 INT32_MIN/MAX 返回失败。真实 UI 集成沿用全部场景，并给识别结果附带生命周期事件，762帧一致。SDL HAL 测试确认没有 keypad/encoder indev，与 pointer indev 双派发实体键的情况不存在。

输入生产者若错误地发送两份互斥结果，UI 不会尝试撤销已发生动作；STM32 InputService 必须保证“一次手势一个结果”。本轮没有实现系统层的手势状态机，因而尚不能宣称真实 GPIO 点击识别已验收。

## 4. 后续 STM32 接入事项

1. 升级 `App/Common/app_events.h` 的队列记录，推荐 typedef 公共 `ui_physical_input_event_t`；旧 type/value 没有 action/time，不能直接 cast 或推断长按。
2. InputService 完成全部键时序识别与四相解码，输出 key/action/归一化 delta/统一单调 timestamp；按上限拆分 delta，清零 reserved。
3. InputTask 仅调用现有 FreeRTOS post 队列函数，处理队列失败；UiTask 收队列后调用正式 handle_input_event，记录 false，再运行 LVGL handler。
4. PowerService 处理实体 POWER、开关机及屏幕硬件；状态通知交 UiTask 调用 apply_display_state。现有触摸菜单/异步 UI 命令仍走正式后台与 ACK，不要再次识别物理长按。
5. 继续使用原触摸校准缓存与 pointer/event 双路径，不额外创建实体键 LVGL indev，不手工重复触发按钮 action。

完整 C 定义、映射、示例和 PC 操作见 [输入架构与队列契约](输入架构重构_20261009.md)。
