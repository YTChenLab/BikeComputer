# USART1 资源安装协议 V1

本协议只封装安装事务，Resource Package V1、37 项资源、CRC/SHA、Resource ID 和 A/B 分区不变。通信为已确认的 USART1：PA9 TX、PA10 RX，115200、8N1，无流控。无 USB CDC 实现，不占用 USART2/GNSS 的 DMA。

## 帧格式

所有整数小端，无填充。请求最多 280 Byte，回复固定 148 Byte。

| 偏移 | 字节数 | 字段 |
|---:|---:|---|
| 0 | 4 | ASCII `BCRI` |
| 4 | 1 | 协议版本，固定 1 |
| 5 | 1 | 命令；回复为请求命令 OR 0x80 |
| 6 | 2 | payload 长度，最大 260；回复固定 128 |
| 8 | 4 | session；查询/诊断/复位为 0，BEGIN 由 PC 随机生成非零值 |
| 12 | 4 | sequence；BEGIN=0，DATA 从 1 递增，COMMIT/ABORT 使用 next_sequence |
| 16 | 4 | CRC32 |
| 20 | N | payload |

CRC-32/ISO-HDLC 覆盖 `header[0:16] + payload`，不覆盖 CRC 字段自身。固件共享原 `ResourcePackage_Crc32Update`，初值及最终异或均为 FFFFFFFF；PC 使用标准库 zlib.crc32。没有第二套资源包解析器或 SHA256 实现。

接收器丢弃上电 ASCII 日志和噪声，滑动搜索 magic；非法版本/长度/响应命令位直接丢弃。帧 CRC 错误不回复，因为 session/序号不可信；PC 超时重发。合法帧中的错误命令/状态返回 NACK，形式与 ACK 相同，payload.code 非零。

## 命令

| 值 | 名称 | 请求 payload | 行为 |
|---:|---|---|---|
| 1 | HELLO | 空 | 返回产品 BIKE 标识、96-bit UID、协议能力、资源兼容版本、状态 |
| 2 | STATUS | 空 | 独立查询活动槽、包版本/长度/SHA、会话进度、映射锁定状态 |
| 3 | BEGIN | u32 package_size | 仅 INSTALL 且未锁定时调用 ResourceStorage_Begin，选择非活动槽；seq=0 |
| 4 | DATA | u32 offset + 1..256 Byte | offset 必须等于已接收量；除最后一包外固定 256 Byte，偏移按 256 对齐 |
| 5 | COMMIT | 空 | 先由既有 storage/manager 完整验证，再原子写入 metadata；收齐字节不等于提交成功 |
| 6 | ABORT | 空 | 结束未提交会话，撤销写授权，旧活动槽不变 |
| 7 | DIAG | u32 flags | bit0=0 非破坏诊断；bit0=1 请求破坏诊断必返回 NO_SAFE_AREA；其他位拒绝 |
| 8 | MAINTENANCE | 空 | ACK 同步发完后设置单次维护复位标记并复位；不解除现有映射锁 |
| 9 | REBOOT | 空 | ACK 同步发完后清除维护标记并正常复位；未提交会话先中止 |

查询、诊断、复位的 sequence 为 PC 请求标识，设备原样回传；PC 使用随机起始查询号，避免陈旧串口回复混入。更新命令采用独立非零 session 和严格顺序。不同 session 不得写同一会话。

DIAG 在进行安装事务或 UI_PENDING 期间返回 BUSY；UI_ACTIVE 时仅执行可安全读取的映射/MPU/边界项目，间接命令明确跳过。完整非破坏诊断应先进入维护模式。

## 普通回复 payload

以下偏移相对 payload，不包含 20 Byte 帧头。

| 偏移 | 内容 |
|---:|---|
| 0 | u32 code，0=ACK，非零=NACK |
| 4 | u32 detail；STORAGE 错误时为 resource_storage_status_t |
| 8 | mode：0 BOOT、1 INSTALL、2 UI_PENDING、3 UI_ACTIVE |
| 12 | active_slot：0 A、1 B、FFFFFFFF 无有效活动槽 |
| 16 | received：storage 已成功写入并回读确认的字节数 |
| 20 | total：BEGIN 的期望长度 |
| 24 | 已提交包版本 |
| 28 | 已提交包长度 |
| 32..63 | 已提交包 payload_sha256，原始 32 Byte；无活动包时全零 |
| 64..75 | MCU UID，3 个 u32 小端顺序 |
| 76 | session |
| 80 | next_sequence |
| 84 | target_slot |
| 88 | last_error；异步 CRC、超时、接收溢出也在这里报告 |
| 92 | last_detail，仅 last_error 非零时有意义 |
| 96 | locked：Q4-2 永久映射锁是否有效 |
| 100 | 协议能力版本，1 |
| 104 | committed：本次安装事务已提交标志；持久状态仍以 active_slot/包摘要为准 |
| 108 | running：是否存在未提交会话 |
| 112 | 产品 ID，0x42494B45 |
| 116 | 资源固件兼容版本，1；不是工程目录 v2.0 或 UI 发布版本 |
| 120 | 分包字节数，256 |
| 124 | 会话空闲超时，30000 ms |

ACK.DATA 表示该块已经通过 BSP 编程和回读验证；ACK.COMMIT 才表示完整校验和 metadata 提交成功。PC 必须再发 STATUS，对活动槽、版本、长度和 SHA 做独立确认，之后才发 REBOOT。即使 COMMIT ACK 丢失，设备也可能已经提交，不能据超时断言失败或强行回滚。

## 重试、超时与恢复

- PC 同时只保留一个未确认请求，重试时重发完全相同的帧。默认 ACK 超时 20 秒，最多 4 次重传；COMMIT 超时 120 秒。
- 设备只缓存最近一次成功变更命令及回复，逐字节比较原请求。BEGIN、DATA、COMMIT、ABORT 的直接重复请求重放 ACK，不重复擦写或提交。普通查询不会挤掉此缓存。
- 更旧的非缓存 DATA、相同序号但不同内容、跳号、非当前 offset、错误 session 均拒绝。PC 不对 STORAGE NACK 盲目重写，避免半写页上的二次编程；应中止后重新 BEGIN。
- 半帧超时 1 秒后丢弃。未提交会话在最后一个成功 BEGIN/DATA 后空闲超过 30 秒自动 Abort；掉电后 RAM 会话丢失，下次从 BEGIN 重新发送，不实现跨复位续传。
- USART1 的 IT 环形缓冲为静态 1024 Byte，CommTask 约每 5ms 排空。溢出/UART 错误会丢弃当前解析状态并中止未提交会话，禁止把丢字节后的数据继续解释成有效安装。
- PC 取消安装时尝试 STATUS + ABORT；无法通信时提示等待设备超时。用户也可明确执行 CLI `abort`。不会未经请求擦除有效活动槽。
- metadata 或候选活动包出现 I/O 错误且无已验证回退槽时，storage 保持未初始化，BEGIN 被拒绝；通信/诊断/复位仍可用。不能把总线读失败报告为空白 Flash。读取恢复后需要重启重新初始化。
- 维护复位标记占用 BKP30/31，互补魔数在启动时立即消费；没有新的 QSPI 标志格式或在线解除映射接口。BKP 行为需实机验证。

## 错误码

| code | 名称 | 含义 |
|---:|---|---|
| 0 | OK | 成功 |
| 1 | FORMAT | 命令字段、flags、session 等格式非法；非法帧头也可能直接丢弃 |
| 2 | CRC | 帧 CRC 错误，丢弃并记 last_error |
| 3 | STATE | 当前模式不允许安装 |
| 4 | SESSION | 会话不存在或 ID 不一致 |
| 5 | SEQUENCE | 跳号或 offset 不是当前已写入量 |
| 6 | LENGTH | 命令 payload 长度非法 |
| 7 | STORAGE | 原存储服务错误或诊断错误，查看 detail/诊断 detail |
| 8 | LOCKED | UI 已固定映射，需维护复位 |
| 9 | BUSY | 已有会话或状态转换中 |
| 10 | TIMEOUT | 半帧/未提交会话超时 |
| 11 | CONFLICT | 旧序号不匹配最近成功缓存帧 |
| 12 | UNSUPPORTED | 未知命令 |
| 13 | TRANSPORT | UART 错误或环溢出导致会话撤销 |
| 14 | NO_SAFE_AREA | 没有可证明安全的擦写诊断区域 |

STORAGE detail 原枚举：0 OK、1 EMPTY、2 ARGUMENT、3 STATE、4 RANGE、5 IO、6 VERIFY、7 CONFLICT。普通回复的 code/detail 与诊断尾部的 BSP detail 命名空间不同。

## DIAG 尾部

DIAG 的 payload[0..75] 仍是 code/detail/mode/活动包/UID；payload[76..127] 替换为 13 个 u32：

| 索引 | 字段 |
|---:|---|
| 0 | result，同顶层 code |
| 1 | passed_mask |
| 2 | skipped_mask；跳过项目的零值不能解释为硬件通过 |
| 3 | JEDEC 三字节小端组合，预期 EF 40 18，即 0x001840EF |
| 4 | SR1 |
| 5 | SR2 |
| 6 | 间接读取 BSP 状态 |
| 7 | 进入映射的 BSP 状态 |
| 8 | MPU 配置错误，0 表示静态配置检查通过 |
| 9 | 可证明安全的 scratch 字节数，当前固定 0 |
| 10 | 本次读取样本长度，32 |
| 11 | UI 映射分支的样本 XOR，仅表示实际发生读取，不代替 CRC/SHA |
| 12 | diagnostic_detail：失败时的 BSP 状态；NO_SAFE_AREA 时为 14 |

mask 位：bit0 JEDEC/初始化、bit1 状态寄存器/BUSY、bit2 WREN 后确认 WEL 并执行 WRDI 清除、bit3 间接和映射样本一致或已有固定映射可读、bit4 getter 正负边界、bit5 MPU 的 enable/地址/大小/只读/XN/Normal non-cacheable 属性。

未映射维护模式下，理想 passed_mask=63、skipped_mask=0、MPU error=0；UI 已固定映射时，理想 passed_mask=56、skipped_mask=7。mask 结果是实际设备执行后的报告，离线 NOR 模型不会证明这些硬件检查通过。

Reserved 分区没有可擦写所有权声明。诊断没有任意地址写/擦命令，也不把有效或备用 A/B 槽当作 scratch。flags=1 只会报告拒绝并保留非破坏项目；跨页编程和擦除后回读能力继续复用原 BSP，并由明确的资源安装事务使用。
